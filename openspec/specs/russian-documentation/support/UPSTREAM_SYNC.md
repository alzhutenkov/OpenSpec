# Обновление оригиналов и повторный перевод

Этот порядок дополняет [актуальную SDD](../spec.md). Правила находятся вне `docs/ru/`, поэтому доступны агенту при повторном создании русского комплекта.

## Получите изменения исходного проекта

Перед слиянием сохраните текущую работу и проверьте remote:

```bash
git status --short
git remote -v
```

`origin` указывает на ваш форк, `upstream` на `https://github.com/Fission-AI/OpenSpec.git`. Если `upstream` отсутствует, добавьте его:

```bash
git remote add upstream https://github.com/Fission-AI/OpenSpec.git
```

Существующее имя remote не заменяется автоматически. Получите изменения и определите основную ветку upstream:

```bash
git fetch upstream
git remote set-head upstream --auto
git log --oneline HEAD..upstream/HEAD
git diff --stat HEAD...upstream/HEAD
```

Если `upstream/HEAD` не определился, уточните целевую ветку. В обновляемой ветке форка выполните обычное слияние:

```bash
git merge upstream/HEAD
```

Обычное слияние сохраняет обе истории. Для перевода не нужны пересоздание репозитория, переписывание коммитов или принудительная отправка.

## Разрешите конфликт README

Сохраните новую английскую версию и один блок между `<!-- russian-docs:start -->` и `<!-- russian-docs:end -->`. Кнопка ведёт в `docs/ru/README.md`, её изображение находится в `assets/russian-docs-button.svg`.

После разрешения конфликтов добавьте исправленные файлы через `git add` и завершите слияние командой `git commit`. Незавершённое слияние с конфликтами можно отменить через `git merge --abort`.

## Поручите агенту полный проход перевода

Пример запроса:

> Приведи русский комплект к актуальным оригиналам по openspec/specs/russian-documentation/spec.md. Обработай весь согласованный набор, сохрани дерево файлов и структуру страниц, обнови переводы и сведения о сверенной версии. Проверь результат и исправь ошибки.

Агент определяет источники по текущему дереву и SDD, а не по наличию прежних переводов. Сверяет новые, изменённые, исчезнувшие и переименованные страницы с [реестром](translation-manifest.json). Русский каталог можно создать повторно по [правилам перевода](TRANSLATION_RULES.md); сами правила сохраняются вне него.

У корневого `README.md` перевод располагается в `docs/ru/README.md`. В нём сохраняется содержание оригинала и отдельная ссылка на SDD. Объяснение обновления форка в README не добавляется.

## Обновите сведения после сверки

Для каждой проверенной страницы агент сохраняет путь оригинала, путь перевода, коммит, blob и состояние. Версию записывает после сверки содержимого и примеров. Перевод исчезнувшего оригинала сохраняется до явного решения по конкретной записи.

Если нужной версии нет в локальной истории, сначала проверьте SHA и полноту клона. Для shallow-клона историю можно получить из соответствующего remote через `git fetch --unshallow origin`.

После прохода агент сверяет полноту, структуру, ссылки, изображения и технические примеры. Исправляет ошибки и отражает ограничения незавершённых оригиналов в [результатах сверки](VALIDATION.md). Обновление перевода можно оформить отдельным коммитом после слияния английских изменений.
