# Организация русского комплекта

## Context

OpenSpec уже инициализирован в репозитории: используется `openspec/config.yaml` со схемой `spec-driven`. Для работы из Codex установлены шесть навыков в общую проектную папку `.agents/skills/` командой `openspec init --tools agents`.

`docs-lab/` содержит актуальные материалы и заготовки страниц. `docs/README.md` помечает `docs/` как прежний набор. Сайт собирается из `docs-lab/` по `website/docs.sync.config.mjs`.

Мотивация и область изменения: [proposal.md](proposal.md). Проверяемый контракт: [spec.md](specs/russian-documentation/spec.md).

## Goals / Non-Goals

**Goals:** отдельные русские файлы, минимальное пересечение с upstream, проверяемое соответствие оригиналам и обычное слияние Git с сохранением истории.

**Non-Goals:** перевод сообщений самой программы, исходного кода, машинных инструкций и шаблонов; публикация русской версии сайта; автоматическое разрешение любых будущих конфликтов Git.

## Decisions

### 1. Сохранять дерево оригиналов внутри одного каталога

```text
docs/ru/
├── README.md                  # русская точка входа
├── UPSTREAM_SYNC.md           # порядок обновления
├── translation-manifest.json # соответствия и проверенные версии
├── assets/                   # локальные изображения перевода
├── docs-lab/                 # актуальные материалы
├── docs/                     # прежние руководства с предупреждениями
├── project/                  # корневые документы
└── ...                       # README подсистем по исходным путям
```

Латинские имена файлов и регистр сохраняются. Перевод `README.md` проекта находится в `docs/ru/project/README.md`, чтобы не совпадать с русской главной страницей.

Альтернатива: `*.ru.md` рядом с каждым оригиналом. Она распределяет перевод по исходному дереву. Замена оригиналов переводом создаёт пересечение с каждым английским обновлением; отдельное дерево этого избегает.

### 2. Явно определить набор источников

- Все отслеживаемые Markdown из `docs-lab/`.
- Все отслеживаемые Markdown из `docs/`, кроме самого `docs/ru/`.
- `README.md`, `README_OLD.md`, `CONTRIBUTING.md`, `SECURITY.md`, `MAINTAINERS.md`, `install.md`, `CHANGELOG.md`, `openspec-parallel-merge-plan.md`.
- `scripts/README.md`, `skills/README.md`, `website/README.md`, `.changeset/README.md`, `.devcontainer/README.md`, `.github/workflows/README.md`.

Машинные файлы `AGENTS.md`, `.agents/`, `.codex/`, `skills/openspec-*/`, `schemas/`, шаблон PR, код, тесты, `openspec/` и сгенерированные страницы сайта исключаются с записанной причиной. Новые области включаются явно.

Реестр хранит конкретные пары путей. Поиск новых источников ограничен согласованными областями. Изменение и удаление переводов выполняется только по точной записи реестра, а не очисткой по маске.

### 3. Хранить проверенную версию для каждой страницы

Запись реестра: `source`, `translation`, `sourceCommit`, `sourceBlob`, `status`. Состояния: `pending`, `draft`, `reviewed`, `source-incomplete`.

`source-incomplete` допускается при приёмке перевода всего доступного текста. На странице нужна видимая пометка «Оригинал этой страницы ещё не завершён.». Проверка оставляет это состояние в отчёте как предупреждение. Отсутствие пометки на странице или статуса в реестре для обнаруженного незавершённого оригинала считается ошибкой. Проверенные версии, полнота перевода доступного текста и навигация проверяются и для таких страниц.

Сравнение с содержимым проверенного Git blob выявляет отставание (`stale`). Отчёт также показывает новые источники, отсутствующие переводы и исчезнувшие оригиналы. Коммит и blob обновляются после сверки текста, примеров и ссылок.

CRLF нормализуется при сравнении, чтобы Windows не давал ложное отставание. Блок русского входа в основном README исключается из сравнения английского текста. В начале перевода указываются оригинал и проверенная версия.

Альтернатива: одна дата для всего комплекта. Она не показывает, какая страница отстала и с чем её сравнивать.

### 4. Защитить технические примеры и навигацию

Команды, флаги, ключи, пути, API, служебные заголовки `Requirement:` / `Scenario:` и ключевые слова `SHALL`, `WHEN`, `THEN` сохраняются. Для реальных сообщений CLI сохраняется оригинал и добавляется русское объяснение.

Ссылки направляются в русский комплект по реестру. После перевода заголовка сохраняется действующий якорь. Внешние англоязычные переходы отмечаются. Изображения с английским текстом получают перевод либо полное русское пояснение.

Проверка файловых путей использует `node:path`. Markdown-ссылки используют `/` как разделитель URL. Точный регистр и нормализация CRLF обеспечивают переносимость между Windows, macOS и Linux. Локальные тесты проверяют CRLF и путь с пробелами; среда фактического запуска записывается в отчёте.

### 5. Изменять README одним блоком

После логотипа добавляется локальная SVG-кнопка 960×180 и текстовая ссылка. Блок ограничен `<!-- russian-docs:start -->` и `<!-- russian-docs:end -->`.

При конфликте этот блок переносится целиком в новую английскую версию README. Само изображение находится в `docs/ru/assets/`, без внешних шрифтов и скриптов. Остальной английский README сохраняется.

### 6. Сначала сливать оригиналы, затем сверять переводы

Исходный репозиторий: `https://github.com/Fission-AI/OpenSpec.git`. Форк остаётся `origin`; исходный проект подключается как `upstream`. Основная ветка определяется через `upstream/HEAD`.

Обычный `git merge` сохраняет историю. Обновление оригиналов и обновление перевода оформляются раздельными коммитами. Переписывание истории и принудительная отправка для русификации не требуются.

`node scripts/check-russian-docs.mjs` запускается вручную и выдаёт отчёт без записи файлов и сети. `--strict` возвращает ненулевой код при незавершённом покрытии перевода, отставании, неверном реестре, ошибках навигации или необозначенной незавершённости оригинала. Явно помеченный `source-incomplete` остаётся предупреждением и сам по себе не меняет успешный код завершения. `--json` сохраняет предупреждения в отчёте с `severity: "warning"`.

Приёмка состоит из ручного запуска строгой проверки и локальных тестов. Отдельный workflow русской документации удаляется; настройка и прогоны CI на трёх ОС не входят в приёмку. Существующие процессы CI исходного проекта сохраняются.

## Risks / Trade-offs

- Перевод может отставать: проверенная версия и отчёт выделяют затронутые страницы.
- Upstream может менять README или добавить собственный `docs/ru/`: Git-конфликты остаются возможны. Отдельное дерево и короткий блок ограничивают обычную область пересечения.
- Часть оригиналов ещё не написана: состояние `source-incomplete` и видимая пометка сохраняют видимость пробела. Принимается перевод доступного текста; готовность самого исходного руководства этим не подтверждается.
- Прежние страницы могут описывать старое поведение: русские переводы получают предупреждение и ссылку на актуальный раздел.

## Migration Plan

1. Подключить навыки, создать SDD, русскую главную страницу и кнопку.
2. Создать реестр источников и проверку версий и ссылок.
3. Перевести актуальные материалы, затем прежние руководства и документы проекта.
4. Вручную запустить строгую проверку и локальные тесты, зафиксировать среду и результат. Принимать комплект при отсутствии блокирующих ошибок; явно помеченные незавершённые оригиналы перечисляются как допустимые ограничения.

Откат локализации выполняется отдельным коммитом удаления добавленных русских файлов и блока входа. Английские страницы и прежние коммиты остаются доступными.
