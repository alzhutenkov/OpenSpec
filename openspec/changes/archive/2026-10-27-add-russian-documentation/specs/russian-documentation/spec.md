# Русская документация

## Purpose

Обеспечить доступ к документации OpenSpec на русском языке в отдельном каталоге и сопровождать перевод вслед за исходным репозиторием с сохранением оригинальных страниц и истории Git.

## ADDED Requirements

### Requirement: Отдельный русский комплект

Проект SHALL предоставлять русскую документацию в `docs/ru/` с собственной главной страницей и навигацией. Английские оригиналы SHALL оставаться доступными по прежним путям. Каждый документ согласованного набора SHALL иметь перевод или явно обозначенное состояние незавершённой работы.

#### Scenario: Открытие русского раздела
- **WHEN** читатель открывает `docs/ru/README.md`
- **THEN** получает русскую навигацию по доступным руководствам
- **AND** видит, какие материалы ещё не переведены или не завершены в оригинале

### Requirement: Сохранение исходной истории

Русификация SHALL добавляться новыми файлами без замены и перемещения английских документов и без переписывания существующих коммитов. Основной README SHALL сохранять английский текст и получать только отдельный блок русского входа.

#### Scenario: Проверка изменений в Git
- **WHEN** сопровождающий сравнивает состояние до и после русификации
- **THEN** английские страницы доступны на прежних путях с прежним содержимым
- **AND** изменения README ограничены блоком русского входа
- **AND** прежние коммиты остаются в истории

### Requirement: Крупная кнопка в README

Корневой README SHALL содержать крупную кнопку «Документация на русском» перед первым содержательным разделом. Кнопка SHALL открывать `docs/ru/README.md` в той же ветке и иметь доступное русское описание и текстовую ссылку на ту же страницу.

#### Scenario: Вход через GitHub
- **WHEN** читатель открывает основной README
- **THEN** видит кнопку без раскрытия дополнительных блоков
- **AND** нажатие открывает русский раздел

#### Scenario: Изображение недоступно
- **WHEN** просмотрщик не отображает изображение кнопки
- **THEN** текстовая ссылка позволяет открыть тот же раздел

### Requirement: Полнота и точность перевода

Перевод SHALL передавать все содержательные разделы, условия, ограничения, предупреждения и примеры оригинала. Команды, флаги, пути, ключи конфигурации, API и служебный синтаксис OpenSpec SHALL сохранять работоспособность. Английские сообщения CLI SHALL сопровождаться русским объяснением с сохранением исходного сообщения.

#### Scenario: Копирование примера
- **WHEN** читатель копирует команду или конфигурацию из русского руководства
- **THEN** получает тот же технический результат, что в исходном примере
- **AND** пояснения позволяют понять действие без знания английского

#### Scenario: Разбор сообщения об ошибке
- **WHEN** руководство объясняет сообщение CLI
- **THEN** читатель может сопоставить исходный текст с терминалом и прочитать русское объяснение

### Requirement: Русские переходы между страницами

Ссылка на документ с готовым переводом SHALL открывать русский файл и существующий раздел. Переход на английский оригинал или англоязычный внешний ресурс SHALL быть обозначен. Локальная навигация SHALL работать в GitHub и Markdown-просмотрщиках Windows, macOS и Linux.

#### Scenario: Переход после перевода заголовка
- **WHEN** читатель следует по ссылке на раздел другой страницы
- **THEN** открывается соответствующий русский раздел с действующим якорем

#### Scenario: Работа на Windows и Linux
- **WHEN** комплект клонируют на Windows или Linux
- **THEN** относительные ссылки разрешаются без путей конкретного компьютера
- **AND** точный регистр имён файлов обеспечивает одинаковую навигацию

### Requirement: Проверенная версия оригинала

Для каждого перевода SHALL быть доступны путь оригинала, проверенный коммит и состояние работы. После изменения оригинала отчёт SHALL показывать нуждающийся в сверке перевод. Обновление проверенной версии SHALL подтверждать сверку текста и примеров, а не только изменение метаданных.

#### Scenario: Обновилась одна исходная страница
- **WHEN** её содержимое отличается от проверенной версии
- **THEN** отчёт указывает затронутый перевод и прежнюю проверенную версию
- **AND** неизменившиеся страницы сохраняют состояние актуальности

### Requirement: Получение обновлений из upstream

Сопровождающий SHALL иметь русскую инструкцию обычного слияния изменений Fission-AI/OpenSpec. Добавление переводов SHALL сохранять английские файлы пригодными для этого слияния без конфликтов, вызванных переводом их содержимого. Возможные конфликты блока README SHALL иметь описанный порядок разрешения.

#### Scenario: Upstream изменил английские руководства
- **WHEN** сопровождающий сливает обновления исходного репозитория
- **THEN** английские изменения принимаются по прежним путям, а русские файлы сохраняются отдельно
- **AND** отчёт перечисляет переводы для последующей сверки

#### Scenario: Upstream изменил место вставки кнопки
- **WHEN** Git сообщает конфликт в README
- **THEN** инструкция позволяет сохранить новую английскую версию и один блок русского входа
- **AND** история обеих веток сохраняется

### Requirement: Новые и исчезнувшие источники

Проверка SHALL выявлять новые документы в согласованных областях и исчезнувшие источники. Перевод переименованного или удалённого оригинала SHALL сохраняться до явного решения сопровождающего по его записи в реестре.

#### Scenario: Источник переименован
- **WHEN** после обновления прежний путь отсутствует, а появился новый
- **THEN** отчёт показывает исчезнувший источник и новый непокрытый документ
- **AND** существующий перевод остаётся доступным до пересмотра соответствия

### Requirement: Видимость состояния документации

Русский комплект SHALL различать актуальный `docs-lab/`, прежний `docs/` и незавершённые страницы оригинала. Пометки beta и устаревания SHALL сохраняться. Приёмка комплекта SHALL подтверждать перевод и проверку всего доступного текста всех источников согласованного набора. Незавершённый оригинал SHALL допускаться при приёмке, если его состояние явно обозначено на русской странице и в реестре, а доступный текст переведён и сверен.

#### Scenario: Перевод заглушки
- **WHEN** оригинал содержит заголовки без основного текста или отметку TODO
- **THEN** перевод сохраняет явную отметку незавершённости
- **AND** такая страница не считается готовым руководством
- **AND** её проверенный перевод допускается к приёмке комплекта

#### Scenario: Незавершённость явно обозначена
- **WHEN** весь доступный текст незавершённого оригинала переведён и сверен, на странице есть видимая пометка, а в реестре указан `source-incomplete`
- **THEN** отчёт сохраняет предупреждение о состоянии оригинала
- **AND** это предупреждение само по себе не препятствует приёмке

#### Scenario: Незавершённость скрыта
- **WHEN** незавершённость обнаруженного оригинала не обозначена в реестре или на русской странице
- **THEN** строгая проверка завершается с ошибкой и препятствует приёмке

#### Scenario: Проверка общей готовности
- **WHEN** сопровождающий запускает строгую проверку комплекта
- **THEN** пропуски, черновики перевода, отставание, неверный реестр, битые ссылки и необозначенная незавершённость оригиналов препятствуют приёмке
- **AND** эти ошибки остаются блокирующими и у страниц со статусом `source-incomplete`

### Requirement: Ручная проверка комплекта

Сопровождающий SHALL иметь локальную команду проверки актуальности, покрытия и навигации без обращения к сети и изменения файлов. Приёмка SHALL опираться на её ручной запуск в строгом режиме и результаты локальных тестов с указанием среды.

#### Scenario: Приёмка вручную
- **WHEN** сопровождающий запускает строгую проверку и локальные тесты
- **THEN** получает код завершения и отчёт, различающий блокирующие ошибки и допустимые предупреждения
- **AND** успешный ручной результат позволяет принять комплект без настройки и запуска CI
