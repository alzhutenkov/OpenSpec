# Русская документация

## Purpose

Дать русскоязычному читателю полный комплект документации OpenSpec и позволить сопровождающим обновлять его вслед за оригиналами с сохранением истории проекта.

## ADDED Requirements

### Requirement: Заметный вход из основного README

Основной README SHALL содержать перед первым содержательным разделом крупную кнопку «Документация на русском», ведущую в `docs/ru/README.md`, и текстовую ссылку на ту же страницу. Кнопка SHALL использовать локальный ресурс и доступное русское описание.

#### Scenario: Переход на русском языке
- **WHEN** читатель открывает корневой README в GitHub
- **THEN** видит кнопку без раскрытия дополнительных блоков
- **AND** нажатие открывает русский раздел в той же ветке репозитория

#### Scenario: Изображения отключены
- **WHEN** просмотрщик не загружает изображения
- **THEN** текстовая ссылка позволяет открыть ту же русскую страницу

### Requirement: Полный отдельный комплект

Русский раздел SHALL размещаться в `docs/ru/` и покрывать весь набор документов, определённый в реестре охвата. Для каждого оригинала SHALL быть доступен перевод или явное состояние незавершённой работы. Объявлять комплект полным SHALL быть возможно только после перевода и проверки всех документов набора.

#### Scenario: Проверка полноты
- **WHEN** сопровождающий проверяет готовность русского комплекта
- **THEN** получает список отсутствующих, черновых и устаревших переводов
- **AND** любой такой документ препятствует объявлению комплекта полным

#### Scenario: Новый документ оригинала
- **WHEN** в согласованной области источников появляется новая страница
- **THEN** проверка показывает её как непокрытый документ, даже если записи в реестре ещё нет

### Requirement: Русский текст и точный синтаксис

Переводы SHALL передавать все содержательные разделы, предупреждения, примеры, подписи и ограничения оригинала на русском языке. Команды, имена файлов, ключи конфигурации, API, переменные окружения и синтаксис OpenSpec SHALL сохранять работоспособность. Термины SHALL соответствовать русскому глоссарию.

#### Scenario: Выполнение примера
- **WHEN** читатель копирует команду или конфигурацию из перевода
- **THEN** выполняется тот же пример, что в оригинале
- **AND** пояснения и комментарии понятны на русском языке

#### Scenario: Поиск сообщения об ошибке
- **WHEN** перевод объясняет реальное сообщение CLI
- **THEN** содержит исходное сообщение для сопоставления с терминалом и русское объяснение

#### Scenario: Исходная страница ещё не написана
- **WHEN** оригинал содержит только заголовки или отметку TODO
- **THEN** перевод сохраняет явную отметку незавершённости
- **AND** проверка полноты не принимает эту страницу за готовое руководство

### Requirement: Навигация внутри русского комплекта

Главная страница SHALL давать русскую навигацию по всему комплекту. Ссылка на документ с готовым переводом SHALL вести на русский файл и существующий якорь. Переход к английскому оригиналу, внешнему англоязычному ресурсу или ещё не переведённой странице SHALL быть явно обозначен.

#### Scenario: Переход к другому разделу
- **WHEN** читатель следует по внутренней ссылке из перевода
- **THEN** попадает в соответствующий русский документ
- **AND** фрагмент ссылки открывает нужный раздел после перевода заголовка

#### Scenario: Просмотр на разных платформах
- **WHEN** комплект открыт в GitHub или Markdown-просмотрщике на Windows, macOS либо Linux
- **THEN** относительные ссылки разрешаются с точным регистром имён файлов
- **AND** для работы навигации не требуются абсолютные пути конкретного компьютера

### Requirement: Сохранение оригиналов и истории

Добавление русской документации SHALL сохранять английские оригиналы по прежним путям и существующую историю Git. Оригиналы SHALL оставаться доступными после русификации. Изменение основного README для русского входа SHALL быть отдельным ограниченным блоком.

#### Scenario: Просмотр оригинала
- **WHEN** сопровождающий сравнивает коммиты до и после добавления перевода
- **THEN** оригинальные документы доступны по прежним путям
- **AND** их содержимое сохранено, кроме блока русского входа в основном README
- **AND** перевод добавлен новыми файлами без переписывания старых коммитов

### Requirement: Происхождение и актуальность перевода

Для каждой переводимой страницы SHALL быть доступны путь оригинала, ссылка на проверенную версию и состояние перевода. После изменения, переименования или удаления оригинала проверка SHALL сообщать, какие переводы нуждаются в пересмотре. Изменение версии оригинала SHALL считаться проверенным только после сверки перевода.

#### Scenario: Изменился оригинал
- **WHEN** содержимое исходной страницы отличается от проверенной версии
- **THEN** отчёт указывает оригинал и соответствующий перевод как требующие сверки
- **AND** прежняя проверенная версия остаётся доступна для сравнения

#### Scenario: Переименование или удаление
- **WHEN** исходная страница переименована либо удалена при обновлении
- **THEN** отчёт показывает прежнее соответствие как требующее решения
- **AND** перевод сохраняется до явного решения сопровождающего по конкретной записи

### Requirement: Обновления из исходного репозитория

Сопровождающий SHALL иметь русскую инструкцию получения обновлений Fission-AI/OpenSpec обычным слиянием Git с сохранением истории. После обновления SHALL быть доступен отчёт о влиянии на переводы. Инструкция SHALL объяснять разрешение конфликта в блоке русского входа и пересмотр устаревших страниц.

#### Scenario: Пришло обновление upstream
- **WHEN** сопровождающий сливает новую версию исходного репозитория
- **THEN** английские изменения принимаются как обычные изменения Git
- **AND** русский раздел сохраняется
- **AND** отчёт называет новые, изменённые и исчезнувшие источники для последующей работы

#### Scenario: Конфликт README
- **WHEN** обновление затрагивает место вставки кнопки
- **THEN** инструкция позволяет сохранить новый английский текст и один блок входа в русскую документацию
- **AND** история обеих веток остаётся доступной

### Requirement: Разделение актуальных и прежних материалов

Русская навигация SHALL выделять актуальную документацию `docs-lab/` и прежние руководства `docs/`. Перевод SHALL сохранять пометки beta, устаревания и незавершённости оригинала. Прежний материал SHALL быть обозначен до начала основного текста страницы.

#### Scenario: Открытие прежнего руководства
- **WHEN** читатель открывает перевод из прежнего набора
- **THEN** сразу видит, что материал может быть устаревшим
- **AND** получает ссылку на актуальный русский раздел

#### Scenario: Функция в beta
- **WHEN** оригинал описывает функцию как beta
- **THEN** перевод сохраняет эту пометку и связанные ограничения
