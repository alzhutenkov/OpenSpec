# Организация и сопровождение русского комплекта

## Context

Мотивация: [proposal.md](proposal.md). Контракт: [russian-documentation](specs/russian-documentation/spec.md).

`docs/README.md` помечает `docs/` как прежнюю документацию. `docs-lab/README.md` описывает новый комплект и содержит ещё не написанные страницы. Сайт получает материалы из `docs-lab/` через `website/docs.sync.config.mjs`. Перевод прежнего набора нельзя выдавать за актуальную документацию.

В текущей конфигурации Git есть `origin`, указывающий на форк `alzhutenkov/OpenSpec`. Исходный проект указан в `package.json`: `Fission-AI/OpenSpec`. Зависимости локально не установлены; доступный CLI имеет версию 1.13.1, тогда как `package.json` объявляет 1.15.0.

## Goals / Non-Goals

**Goals:** изолировать перевод от файлов upstream, однозначно сопоставлять документы и показывать отставание от оригиналов.

**Non-Goals:** локализация сообщений CLI, исходного кода, устанавливаемых навыков и шаблонов; публикация русской версии сайта; перевод истории всех предложений OpenSpec. Это отдельные поверхности продукта. Здесь «полная русификация» означает полный русский комплект документации.

## Decisions

### 1. Один корень с сохранением путей оригиналов

```text
docs/ru/
├── README.md                 # русская навигация и состояние готовности
├── TRANSLATION_RULES.md      # правила перевода
├── UPSTREAM_SYNC.md          # обновление из исходного репозитория
├── GLOSSARY.md               # русские термины
├── EXAMPLE_NOTES.md          # русские пояснения к исходному выводу и схемам
├── VALIDATION.md             # результаты и границы проверки
├── translation-manifest.json # планируется: источники, версии, состояния
├── assets/                  # локальная кнопка и переведённые иллюстрации
├── docs-lab/                # актуальная документация, исходные подпапки сохранены
├── docs/                    # прежние руководства, с пометками
├── project/                 # корневые документы, включая перевод README
├── scripts/                 # README скриптов
├── skills/                  # обзор навыков
├── website/                 # README сайта
├── .changeset/              # README для участников
├── .devcontainer/           # README окружения
└── .github/workflows/       # README процессов CI
```

Имена файлов латиницей совпадают с оригиналами. Новые локальные служебные страницы используют имена из дерева выше. Это уменьшает число неоднозначных соответствий и проблем с регистром на Windows.

Альтернатива: `README.ru.md` рядом с каждым оригиналом. Она распределяет перевод по всему дереву и мешает требованию одного отдельного раздела. Замена английских файлов переводами создаёт постоянные конфликты при обновлении.

### 2. Охват фиксируется до перевода

Источники выбираются среди отслеживаемых Git файлов:

| Область | Назначение в русском комплекте |
|---|---|
| Все Markdown из `docs-lab/` | `docs/ru/docs-lab/`, включая служебные карты и заметки с явной пометкой |
| Все Markdown из `docs/`, кроме `docs/ru/` | `docs/ru/docs/`, как прежние материалы |
| `README.md`, `README_OLD.md`, `CONTRIBUTING.md`, `SECURITY.md`, `MAINTAINERS.md`, `install.md`, `CHANGELOG.md`, `openspec-parallel-merge-plan.md` | `docs/ru/project/`, с сохранением типа и статуса документа |
| `scripts/README.md`, `skills/README.md`, `website/README.md`, `.changeset/README.md`, `.devcontainer/README.md`, `.github/workflows/README.md` | Соответствующий путь внутри `docs/ru/` |

Исключения: машинные инструкции `AGENTS.md`, `.agents/`, `.codex/`, устанавливаемые `skills/openspec-*/SKILL.md`, шаблоны `schemas/`, `.github/PULL_REQUEST_TEMPLATE.md`, спецификации и исторические изменения `openspec/`, код и фикстуры `src/` и `test/`, сгенерированные страницы сайта. Оригиналы этих файлов продолжают работать без изменений. Причины исключений записываются в реестр охвата; новые области требуют явного решения о включении.

Реестр хранит явные пары `source` / `translation`. Проверка обнаруживает новые исходные документы в указанных областях, но изменяет и удаляет переводы только по точной записи реестра. Глобальная замена или очистка каталога по маске не допускается.

### 3. Версия хранится для каждой страницы

Запись будущего `translation-manifest.json` содержит:

| Поле | Смысл |
|---|---|
| `source` | Путь оригинала от корня репозитория |
| `translation` | Путь русского файла от корня репозитория |
| `sourceCommit` | Полный SHA коммита, по которому выполнена сверка; `null` до сверки |
| `sourceBlob` | Git blob оригинала в этом коммите; `null` до сверки |
| `status` | `pending`, `draft`, `reviewed` или `source-incomplete` |

Состояние `stale` вычисляется сравнением текущего blob оригинала с `sourceBlob`. Изменение другого документа не делает все переводы устаревшими. Для изменённых незакоммиченных оригиналов отчёт тоже требует сверки; блок русского входа между маркерами исключается из сравнения корневого README.

Отчёт выделяет новые источники, отсутствующие переводы, черновики, изменённые и исчезнувшие оригиналы. `source-incomplete` сохраняет видимость недописанных страниц upstream и блокирует заявление о готовности всего комплекта. Переименование показывается как исчезнувший старый источник и новый непокрытый файл; сопровождающий явно обновляет пару.

Для проверки содержимого используется Git blob, а не хеш файла после checkout: иначе CRLF на Windows даёт ложное отставание. Связь с оригиналом видна в начале перевода через относительную ссылку и ссылку на `Fission-AI/OpenSpec/blob/<sourceCommit>/<source>`. Для локальной документации форка используется проверенный permalink форка. Новый SHA записывается только после проверки текста, примеров и ссылок.

Альтернатива: одна дата или один SHA для всего комплекта. Это не показывает, какой перевод отстал, и не даёт сравнить его с проверенным оригиналом.

### 4. Ссылки переписываются по реестру

Документ с готовым переводом открывается внутри `docs/ru/`. Фрагменты ссылок сверяются с переведёнными заголовками. Внешние англоязычные страницы помечаются; ссылки на исходный код, релизы и команды остаются точными.

Изображения без текста можно брать из оригинальных `assets/` относительной ссылкой. Схемы, скриншоты и изображения с важным английским текстом получают русскую версию либо полное русское пояснение. Исходные изображения сохраняются.

Проверка путей использует `node:path`, точный регистр файлов и пути относительно корня. В Markdown используются переносимые URL с `/`; это формат ссылок, а не сборка файловых путей. Проверка запускается на Windows, macOS и Linux, включая checkout с CRLF.

### 5. Кнопка добавляется одним блоком

В корневом README после логотипа размещается блок между `<!-- russian-docs:start -->` и `<!-- russian-docs:end -->`. Он содержит ссылку на `docs/ru/README.md`, SVG шириной 960 и высотой 180 и текстовый запасной вход. SVG хранится в `docs/ru/assets/` и содержит русский текст, без внешних шрифтов, скриптов и сетевых ресурсов.

Кнопка масштабируется по ширине просмотрщика. При конфликте README блок переносится целиком поверх новой версии английского текста. Альтернатива: внешняя картинка-значок. Она зависит от сервиса и недостаточно заметна.

### 6. Сначала принять upstream, затем сверить перевод

Инструкция `UPSTREAM_SYNC.md` описывает проверку чистого дерева, настройку `upstream` на `Fission-AI/OpenSpec`, `fetch`, проверку целевой ветки, обычный `merge` и разрешение конфликтов. История не пересоздаётся, принудительная отправка не требуется. Обновление исходников и пересмотр переводов оформляются раздельно.

Планируется проверка `node scripts/check-russian-docs.mjs`: режим отчёта сообщает расхождения без записи файлов; `--strict` завершает работу с ненулевым кодом при незавершённом покрытии, отставании, невалидном реестре или битых локальных ссылках. Документация команды добавляется одновременно с реализацией. Пока скрипта нет, страницы не предлагают его как существующую команду.

Во время начального перевода строгая проверка запускается вручную. Обязательная проверка CI включается после первого полного покрытия, чтобы незавершённый перевод не блокировал получение английских обновлений. Сетевой доступ для локальной проверки не нужен.

## Risks / Trade-offs

- Отдельная копия постепенно отстаёт → реестр с проверенной версией и отчёт по страницам.
- Часть `docs-lab/` ещё не написана → статус `source-incomplete`, без выдуманного содержимого и обещаний готовности.
- `docs/ru/` вложен в прежний `docs/` → явное исключение русского корня из поиска источников; актуальные переводы идут в `docs/ru/docs-lab/`.
- Минимальная правка README всё равно может конфликтовать → локальные маркеры и инструкция сохранения блока; отсутствие конфликтов не гарантируется.
- Строгая проверка может остановить обновление → сначала отчёт и отдельный коммит слияния, затем перевод и проверка перед объявлением готовности.

## Migration Plan

1. Добавить SDD, русские правила и главную страницу с честной отметкой неполноты; вставить кнопку.
2. Зафиксировать реестр всех источников и исключений, добавить проверку и её документацию.
3. Переводить актуальные руководства, затем справочники, прежние страницы и материалы участников. Каждая партия проходит сверку ссылок и оригинала.
4. Проверить весь комплект и включить строгую проверку CI. До этого не объявлять русификацию завершённой.

Откат: отдельным коммитом убрать блок README и добавленные файлы `docs/ru/`. Английские источники остаются на прежних путях. История сохраняется; `reset` и переписывание опубликованных коммитов не нужны.
