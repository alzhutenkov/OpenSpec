В любом случае новые байты остаются на диске, и архив сообщает, что перемещение было незавершенным, а не успешным с более старой копией.

## 1.0.0

<a id="major-changes"></a>
### Основные изменения

- [#578 (английский)](https://github.com/Fission-AI/OpenSpec/pull/578) [`0cc9d90`](https://github.com/Fission-AI/OpenSpec/commit/0cc9d9025af367faa1688a7b2606a2549053cd3f) Спасибо [@TabishB (английский)](https://github.com/TabishB)! - ## OpenSpec 1.0 — Версия OPSX

  Рабочий процесс был перестроен с нуля. OPSX заменяет старые команды `/openspec:*` с фазовой синхронизацией на систему, основанную на действиях, в которой ИИ понимает, какие артефакты существуют, что готово создать и что открывает каждое действие.

<a id="breaking-changes"></a>
  ### Несовместимые изменения

  - **Старые команды удалены** — `/openspec:proposal`, `/openspec:apply` и `/openspec:archive` больше не существуют.
  - **Файлы конфигурации удалены** — Файлы инструкций для конкретных инструментов (`CLAUDE.md`, `.cursorrules`, `AGENTS.md`, `project.md`) больше не создаются.
  - **Миграция** — запустите `openspec init` для обновления. Унаследованные артефакты обнаруживаются и удаляются с подтверждением.

<a id="from-static-prompts-to-dynamic-instructions"></a>
  ### от статических подсказок к динамическим инструкциям

  **До:** ИИ каждый раз получал одни и те же статические инструкции, независимо от состояния проекта.

  **Теперь:** Инструкции динамически собираются из трех слоев:

  1. **Контекст** — Предыстория проекта из `config.yaml` (технический стек, соглашения)
  2. **Правила** — ограничения, специфичные для артефакта (например, «предлагать пиковые задачи для неизвестных»).
  3. **Шаблон** — Фактическая структура выходного файла.

  ИИ запрашивает у CLI состояние в реальном времени: какие артефакты существуют, что готово к созданию, какие зависимости удовлетворены и что открывает каждое действие.

<a id="from-phase-locked-to-action-based"></a>
  ### от фазовой синхронизации к действию

  **До:** Линейный рабочий процесс — предложение → подать заявку → архивировать. Невозможно было легко вернуться или повторить.

  **Теперь:** Гибкие действия при изменении. Редактируйте любой артефакт в любое время. График артефактов автоматически отслеживает состояние.

  |Команда|Что он делает|
  | -------------------- | ---------------------------------------------------- |
  |`/opsx:explore`|Продумайте идеи, прежде чем вносить изменения.|
  |`/opsx:new`|начать новое изменение.|
  |`/opsx:continue`|создание одного артефакта за раз (пошаговое выполнение).|
  |`/opsx:ff`|создание всех артефактов планирования одновременно (перемотка вперед).|
  |`/opsx:apply`|Реализация задач|
  |`/opsx:verify`|проверка соответствия реализации артефактам.|
  |`/opsx:sync`|синхронизировать дельта-спецификации с основными спецификациями.|
  |`/opsx:archive`|Изменение архива завершено.|
  |`/opsx:bulk-archive`|архивирование нескольких изменений с обнаружением конфликтов.|
  |`/opsx:onboard`|15-минутное пошаговое описание полного рабочего процесса.|

<a id="from-text-merging-to-semantic-spec-syncing"></a>
  ### от слияния текста к синхронизации семантических спецификаций

  **До:** обновления спецификаций требовали ручного объединения или полной замены файлов.

  **Теперь:** В разностных спецификациях используются семантические маркеры, понятные ИИ:

  - `## ADDED Requirements` — Добавлены новые требования
  - `## MODIFIED Requirements` — Частичные обновления (добавление сценария без копирования существующих)
  - `## REMOVED Requirements` — Удаление с указанием причины и примечаний по миграции.
  - `## RENAMED Requirements` — переименовать с сохранением содержимого.

  Архив анализирует их на уровне требований, а не на хрупком сопоставлении заголовков.

<a id="from-scattered-files-to-agent-skills"></a>
  ### от разбросанных файлов к навыкам агентов

  **До:** Более 8 файлов конфигурации в корне проекта + команды с косой чертой, разбросанные по 21 месту для конкретных инструментов в разных форматах.

  **Теперь:** Один каталог `.claude/skills/` с файлами Markdown с интерфейсом YAML. Автоматически обнаруживается Claude Code, Cursor, Windsurf. Совместимость с кросс-редактором.

<a id="new-features"></a>

  - **Навыки адаптации** — `/opsx:onboard` проводит новых пользователей через их первое полное изменение, предлагая задачи с учетом базы кода и пошаговое повествование (11 этапов, ~ 15 минут).

  - **поддерживается 21 инструмент искусственного интеллекта** — Claude Code, Cursor, Windsurf, Continue, Gemini CLI, GitHub Copilot, Amazon Q, Cline, RooCode, Kilo Code, Auggie, CodeBuddy, Qoder, Qwen, CoStrict, Crush, Factory, OpenCode, Antigradity, iFlow и Codex
