# openspec

> OpenSpec помогает вам и агенту согласовать план до написания кода. Этот файл устанавливает CLI и настраивает проект.

Установи OpenSpec и настрой мой проект. Выполняй шаги ниже по порядку и останавливайся там, где это указано.

ЦЕЛЬ: глобально установить CLI OpenSpec и инициализировать проект пользователя.

КРИТЕРИИ ГОТОВНОСТИ:

- `openspec --version` выводит номер версии;
- в подтверждённом пользователем проекте папка `openspec/` создана или обновлена командой `openspec init`;
- пользователю сообщён точный синтаксис вызова OpenSpec в его ИИ-инструменте.

<a id="1-install"></a>
## 1. Установка

Сначала выполни `openspec --version`. Если версия уже выводится, CLI установлен: сообщи об этом, выполни `openspec version --check`, предложи выполнить указанную им команду обновления и переходи к шагу 3. Команда выводит способ обновления по исходному методу установки, если может определить его; иначе используй тот же метод, например `brew upgrade openspec`. При установке через npm или другой менеджер один раз упомяни, что `openspec install` переключает на отдельный файл без Node.js. Только предложи: пользователь мог осознанно выбрать npm. Не повторяй предложение и не переключай способ без просьбы. Самостоятельная смена метода оставляет в PATH две конкурирующие копии.

Установи отдельный исполняемый файл OpenSpec. Node.js не требуется; на Alpine Linux сначала нужен `apk add libstdc++ libgcc`. Покажи команду для ОС пользователя и выполни только после подтверждения, затем переходи к шагу 3:

```bash
# macOS/Linux
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | sh
```

```powershell
# Windows (PowerShell)
irm https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.ps1 | iex
```

Если пользователь предпочитает менеджер пакетов или установщик завершился ошибкой, переходи к шагу 2.

<a id="2-package-manager-only-if-step-1-did-not-install-it"></a>
## 2. Менеджер пакетов (только если шаг 1 не завершил установку)

Выполни `node --version`. Требуется Node.js 20.19.0 или выше. Если Node отсутствует или устарел, не устанавливай его, не переключай версии и не меняй менеджер версий самостоятельно. Остановись и оставь пользователю следующий шаг: https://nodejs.org или команду переключения на более новую версию через его менеджер, например nvm.

Используй доступный в PATH менеджер, предпочитая npm:

```bash
npm install -g @fission-ai/openspec@latest
pnpm add -g @fission-ai/openspec@latest
bun add --global @fission-ai/openspec@latest
yarn global add @fission-ai/openspec@latest   # только Yarn 1.x
```

Не выбирай по lock-файлу проекта: глобальная установка не связана с установкой зависимостей репозитория. Если ни один из четырёх менеджеров недоступен, остановись и сообщи об этом; не придумывай другой способ. На Nix направь пользователя к разделу Nix на https://openspec.dev/docs/installation.

Покажи точную команду и получи подтверждение перед запуском: программа устанавливается вне проекта, и пользователь может предпочитать другой менеджер пакетов.

Остановись и спроси снова, если требуются sudo или права администратора, возникает ошибка разрешений либо глобальная папка исполняемых файлов отсутствует или не настроена. Не редактируй файлы запуска оболочки (.bashrc, .zshrc, .profile, fish, профиль PowerShell) и не запускай команды настройки, которые их меняют. Покажи необходимое изменение и предоставь пользователю выполнить его самостоятельно.

## 3. PATH

Выполни `openspec --version`. Если команда не найдена, возможно, её не видит только текущая оболочка. Укажи папку установки: установщик отдельного файла выводит её, по умолчанию это `~/.local/bin`; у менеджеров пакетов свои глобальные папки. Объясни добавление папки в PATH для ОС и оболочки пользователя и дождись подтверждения. На Windows установщик сам добавляет папку в пользовательский PATH; новый терминал подхватывает её. Если выводится версия старее указанной при установке, прежняя копия перекрывает новую в PATH. Сообщи обе версии вместо продолжения. Если используется менеджер версий, объясни его роль, не обходя его правками PATH: nvm и fnm привязывают CLI к версии Node, активной при установке, а asdf и volta могут требовать обновления обёртки.

<a id="4-initialize"></a>
## 4. Инициализация

Определи расположение `openspec/` и начни с обоснованного предположения. Почти всегда подходит корень проекта пользователя. Назови папку и дай возможность исправить выбор, например: «Вы в ~/code/acme-api, поэтому настрою OpenSpec здесь». Предпочитай корень системы контроля версий текущему каталогу; в монорепозитории назови выбранный пакет и объясни выбор. Другую папку передавай явно: `openspec init <path> --tools <ids>`.

Init создаёт `openspec/` по указанному пути и не предупреждает об ошибочном выборе. Если это домашняя или временная папка либо каталог без проекта, остановись и уточни расположение проекта.

Определи ИИ-инструменты пользователя. Снова начни с предположения: вероятно, ты работаешь внутри одного из них. Назови его и спроси о других, предложив Claude Code, Cursor, Copilot, Codex. Объясни последствие: каждый выбранный инструмент получает свои файлы навыков и команд в проекте; повторный init позволяет добавить другие позже. Сопоставь инструменты с идентификаторами из `openspec init --help`: Copilot соответствует `github-copilot`, Zoo Code соответствует `roocode`. Флаг `--tools` принимает список через запятую; перечисли все выбранные инструменты.

`openspec init --tools <ids>` автоматически, без вопроса, удаляет остатки старых версий, включая домашние запросы `opsx-*.md` (у Codex они в `~/.codex/prompts`). До запуска найди папки `.../commands/openspec/`, блоки OpenSpec в CLAUDE.md, AGENTS.md и домашние запросы `opsx-*.md`. Перечисли найденное, прямо скажи, что init удалит эти данные, и дождись согласия. Если ничего нет, сообщи об этом и продолжай без дополнительного вопроса. Существующая папка `openspec/` не мешает: init обновляет её, сохраняя спецификации и изменения.

Затем выполни `openspec init --tools <ids>`, добавив путь, если выбран не текущий каталог.

<a id="5-report"></a>
## 5. Отчёт

Не предполагай результат: передай фактический вывод init. Укажи количество и расположение навыков и команд, строку конфигурации, примечания «Setup required» и указания перезапуска или перезагрузки. Некоторые инструменты поддерживают только навыки и закономерно создают ноль команд; само по себе это не ошибка. Если init сообщил, что ничего не создано, передай предложенное исправление вместо повторного запуска.

В конце назови точный синтаксис вызова OpenSpec в инструменте пользователя. Возьми его из созданных файлов, а не из итоговой строки init: знаки различаются (`/opsx:propose`, `/opsx-propose`, `@opsx-propose` в Amazon Q). Инструменты с навыками вместо команд используют имя навыка: `/openspec-propose`, `$openspec-propose` в Codex или `/skill:openspec-propose` в Kimi Code.
