# Русский глоссарий

Используйте одинаковые названия в руководствах и SDD. Технические имена файлов и команд сохраняйте в исходном написании.

| Термин оригинала | Русское название | Значение |
|---|---|---|
| Spec-driven development, SDD | Разработка по спецификациям | Сначала согласуются требования, затем реализация |
| Specification, spec | Спецификация | Проверяемое описание поведения |
| Requirement | Требование | Одно правило поведения продукта |
| Scenario | Сценарий | Условие и ожидаемый результат |
| Capability | Возможность продукта | Область поведения с собственной спецификацией |
| Change | Изменение | Отдельный набор планируемых доработок |
| Proposal | Предложение | Зачем нужно изменение и что оно меняет |
| Design | Техническое решение | Как будет устроена реализация |
| Tasks | Задачи | Список работ с отметками выполнения |
| Artifact | Артефакт | Документ изменения: предложение, спецификация, решение или задачи |
| Delta spec | Изменения спецификации | Добавляемые, изменяемые и удаляемые требования |
| Workflow | Рабочий процесс | Порядок действий при работе над изменением |
| Skill | Навык | Инструкции для ИИ-помощника, запускающие рабочий процесс |
| Schema | Схема | Описание артефактов и их зависимостей |
| Profile | Профиль | Выбранный набор рабочих процессов |
| Archive | Архивирование | Обновление основных спецификаций и перенос завершённого изменения в архив |
| Store | Хранилище спецификаций | Отдельный репозиторий с планами и требованиями |
| Workset | Рабочий набор | Хранилище и связанные репозитории в одном рабочем окружении |
| Upstream | Исходный репозиторий | Проект Fission-AI/OpenSpec, из которого принимаются обновления |
| Fork | Форк | Собственная копия репозитория с общей историей |
| Merge | Слияние | Объединение изменений с сохранением истории веток |
| Source commit | Проверенный коммит оригинала | Версия, по которой выполнена сверка перевода |
| Stale translation | Устаревший перевод | Перевод, который нужно сверить с изменившимся оригиналом |

Маркеры `Requirement:`, `Scenario:`, `ADDED Requirements` и ключевые слова `SHALL`, `WHEN`, `THEN` в исполняемых примерах спецификаций остаются английскими: их распознаёт OpenSpec.

## Как читать служебные маркеры

| Маркер | Значение по-русски |
|---|---|
| `Requirement:` | Требование |
| `Scenario:` | Сценарий |
| `SHALL`, `MUST` | Обязательное условие: «должен» |
| `GIVEN` | Исходное состояние: «дано» |
| `WHEN` | Условие: «когда» |
| `THEN` | Ожидаемый результат: «тогда» |
| `AND` | Дополнительное условие или результат: «и» |
| `ADDED Requirements` | Добавленные требования |
| `MODIFIED Requirements` | Изменённые требования |
| `REMOVED Requirements` | Удаляемые требования |
| `RENAMED Requirements` | Переименованные требования |

Перевод значений помогает читать примеры. Само написание маркеров в файле спецификации сохраняйте.
