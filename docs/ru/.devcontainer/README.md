# Настройка контейнера разработки

этот каталог содержит конфигурацию контейнера разработки VS Code для разработки OpenSpec.

<a id="whats-included"></a>
## Что включено

- **Node.js 22 LTS** — среда выполнения TypeScript/JavaScript (сам OpenSpec поддерживает Node 20.19.0 и новее)
- **pnpm** — быстрый менеджер пакетов, экономящий дисковое пространство.
- **Git + GitHub CLI** — инструменты контроля версий.
- **Расширения VS Code**:
  - ESLint & Prettier для качества кода
  - Vitest Explorer для запуска тестов.
  - GitLens для расширенной интеграции с git.
  - Линза ошибок для встроенного выделения ошибок.
  - Проверка правописания кода
  - Путь IntelliSense

<a id="how-to-use"></a>
## Как использовать

<a id="first-time-setup"></a>
### Первая установка

1. **Установите необходимые условия** (на локальном компьютере):
   - [VS Code (английский)](https://code.visualstudio.com/)
   - [Рабочий стол Docker](https://www.docker.com/products/docker-desktop)
   - [Расширение Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers)

2. **Открыть в контейнере**:
   - Откройте этот проект в VS Code.
   - вы увидите уведомление: «Папка содержит файл конфигурации Dev Container».
   - нажмите «Повторно открыть в контейнере».

   ИЛИ

   - Открыть палитру команд (`Cmd/Ctrl+Shift+P`)
   - Введите «Контейнеры разработки: повторно открыть в контейнере».
   - Нажмите Enter.

3. **Дождитесь установки**:
   - Контейнер будет собран (первый раз займет несколько минут).
   - `pnpm install` запускается автоматически через `postCreateCommand`.
   - все расширения устанавливаются автоматически.

<a id="daily-development"></a>
### Ежедневная разработка

После установки контейнер сохраняет вашу среду разработки:

```bash
# Запустить сборку для разработки.
pnpm run dev

# Запустите CLI в разработке.
pnpm run dev:cli

# Запуск тестов.
pnpm test

# запуск тестов в режиме просмотра.
pnpm test:watch

# Сборка проекта.
pnpm run build
```

<a id="ssh-keys"></a>
### Ключи SSH

ваши SSH-ключи монтируются в `~/.ssh` только для чтения, поэтому операции git без проблем работают с GitHub/GitLab.

<a id="rebuilding-the-container"></a>
### Восстановление контейнера

Если вы измените `.devcontainer/devcontainer.json`:
- Палитра команд → «Контейнеры разработки: перестроить контейнер»

<a id="benefits"></a>
## Преимущества

- нет необходимости устанавливать Node.js или pnpm на локальный компьютер.
- единообразная среда разработки для всех членов команды.
- изолирован от других проектов Node.js на вашем компьютере.
- все зависимости и инструменты помещены в контейнеры.
- простая адаптация для новых разработчиков.

<a id="troubleshooting"></a>
## Устранение неполадок

**Контейнер не собирается:**
- убедитесь, что Docker Desktop работает.
- проверьте, достаточно ли выделенной памяти Docker (рекомендуется 4 ГБ и более).

**Расширения не отображаются:**
- перестройте контейнер: «Контейнеры разработки: перестроить контейнер».

**Проблемы с разрешениями:**
- Контейнер запускается от имени пользователя `node` (не root).
- файлы, созданные в контейнере, принадлежат этому пользователю.
