# Правила перевода документации

Весь русский комплект хранится в `docs/ru/`. Проверяемые требования находятся в [SDD-спецификации](../../openspec/changes/add-russian-documentation/specs/russian-documentation/spec.md).

## Переводите весь согласованный набор

**Актуальные материалы:** все Markdown-страницы `docs-lab/`. Сохраняйте структуру подпапок внутри `docs/ru/docs-lab/`.

**Прежняя документация:** все Markdown-страницы `docs/`, кроме самого `docs/ru/`. Размещайте их в `docs/ru/docs/`. Перед основным текстом указывайте, что материал может быть устаревшим, и давайте ссылку на актуальный русский раздел.

**Материалы проекта:** корневые руководства и README подсистем. Полный список источников и исключений задан в [техническом решении](../../openspec/changes/add-russian-documentation/design.md#2-охват-фиксируется-до-перевода).

Перевод CLI, кода, устанавливаемых навыков и машинных шаблонов относится к отдельным изменениям. Для этого комплекта оригинальные технические файлы сохраняются.

## Сохраняйте смысл и работоспособность примеров

- Переводите заголовки, объяснения, предупреждения, подписи, описания схем и комментарии в примерах.
- Сохраняйте все условия, ограничения, пометки beta и устаревания. Краткий пересказ не заменяет полный перевод.
- Оставляйте команды, флаги, пути, ключи конфигурации, переменные окружения и API в исходном написании.
- Сохраняйте реальные сообщения терминала. После них давайте русское объяснение, чтобы читатель мог найти увиденную ошибку.
- Для изображений с английским текстом добавляйте русскую версию или полное пояснение. Храните новые изображения в русском разделе.

В примерах OpenSpec сохраняйте служебный синтаксис `## ADDED Requirements`, `### Requirement:`, `#### Scenario:`, `SHALL`, `MUST`, `WHEN`, `THEN` и другие распознаваемые маркеры. Заголовок после маркера и описательный текст можно писать по-русски.

Если оригинал содержит заглушку или TODO, переводите её и отмечайте страницу как незавершённую. Не дописывайте поведение продукта от имени оригинала.

## Пишите для читателя без английского

Используйте [глоссарий](GLOSSARY.md). При первом упоминании нового термина давайте русский смысл, затем английское имя в скобках, если оно встречается в интерфейсе или файлах.

Раздел начинайте с ответа или действия. Отделяйте команды терминала от запросов в чате ИИ-помощника. Сохраняйте структуру руководства, чтобы перевод можно было сверить с оригиналом по разделам.

## Проверяйте ссылки

Ссылку на документ с готовым переводом направляйте в русский комплект. Если заголовок переведён, проверяйте и фрагмент после `#`.

Указывайте «английский» у переходов к оригиналам и англоязычным внешним страницам. Если перевода ещё нет, обозначайте это рядом со ссылкой. Не создавайте ссылки на будущие файлы.

Используйте относительные Markdown-ссылки и точный регистр имён. Они должны работать в GitHub и локальном просмотрщике на Windows, macOS и Linux. Английский оригинал не редактируется ради обратной ссылки.

## Фиксируйте проверенную версию

Для каждой страницы в планируемом реестре переводов храните пару путей оригинала и перевода, SHA проверенного коммита, Git blob оригинала и состояние работы.

| Состояние | Значение |
|---|---|
| `pending` | Перевод ещё не сделан |
| `draft` | Текст есть, сверка не завершена |
| `reviewed` | Весь текст, примеры и ссылки сверены с записанной версией |
| `source-incomplete` | Сам оригинал ещё не написан полностью |

Если оригинал отличается от проверенного blob, отчёт должен дополнительно показывать отставание (`stale`). Дата редактирования русского файла сама по себе не подтверждает актуальность.

В начале каждого перевода указывайте ссылку на оригинал и проверенный коммит. Меняйте SHA только после сверки; обновление одного поля без проверки текста не завершает работу.

## Сохраняйте историю Git

Добавляйте перевод новыми файлами. Английские документы не перемещаются и не заменяются русскими. В основном README разрешён отдельный блок входа между маркерами `russian-docs:start` и `russian-docs:end`.

Принимайте обновления исходного проекта обычным слиянием по [инструкции](UPSTREAM_SYNC.md). Оформляйте слияние и обновление перевода раздельными коммитами. Не пересоздавайте репозиторий и не переписывайте опубликованную историю ради русификации.

## Принимайте перевод по результату

Готовая страница должна пройти четыре проверки:

1. Все разделы и ограничения оригинала переданы на русском.
2. Команды и примеры сохраняют смысл и синтаксис.
3. Локальные ссылки, изображения и якоря открываются.
4. Проверенная версия оригинала записана после сверки.

Весь комплект готов, когда каждый источник учтён и каждая страница проверена. Отсутствующие переводы, черновики, отставшие версии и незавершённые исходные страницы остаются видимыми в списке работ. До этого главная страница сообщает о неполноте комплекта.
