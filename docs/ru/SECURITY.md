<a id="security-policy"></a>
# Политика безопасности

<a id="reporting-a-vulnerability"></a>
## Сообщите об уязвимости

Отправьте конфиденциальное сообщение через [GitHub Security Advisories (английский)](https://github.com/Fission-AI/OpenSpec/security/advisories/new). Не создавайте публичное issue для предполагаемой уязвимости.

По возможности укажите затронутую версию, шаги воспроизведения и предполагаемые последствия. Команда стремится подтвердить получение за 3 рабочих дня и выпустить исправление либо принять решение за 30 дней. Авторы подтверждённых сообщений указываются в бюллетене, если не пожелают остаться анонимными.

<a id="supported-versions"></a>
## Поддерживаемые версии

Исправления выходят в последней опубликованной версии npm. Старые версии не исправляются: обновитесь для получения исправления.

<a id="threat-model"></a>
## Модель угроз

OpenSpec является локальным инструментом командной строки. У него нет сервера, сетевого слушателя или привилегированного фонового процесса. Он читает и записывает Markdown внутри каталога запуска по заданным вами путям и с правами вашего пользователя. Во время `openspec update` может предложить самообновление, которое выполняется только с вашего согласия. Отправляет анонимную телеметрию, отключаемую через `OPENSPEC_TELEMETRY=0`.

От этого зависит, что считается уязвимостью:

| Входит в область рассмотрения | Не входит в область рассмотрения |
| --- | --- |
| Выполнение кода при разборе спецификации, конфигурации или шаблона | Чтение или запись пути, который вы сами передали CLI |
| Выход за пределы заданного каталога через недоверенные входные данные | Сообщения статического анализа об объединении путей без недоверенных данных |
| Утечка учётных данных или содержимого файлов через телеметрию либо журналы | Уязвимости devDependencies, не входящих в опубликованный пакет |
| Загрязнение прототипа или инъекция, достижимые из конфигурации либо спецификации | Отказ в обслуживании собственного компьютера из-за собственных входных данных |

Если случай находится на границе, сообщите о нём: команда рассмотрит его вместе с вами.

<a id="published-package-contents"></a>
## Содержимое опубликованного пакета

Пакет npm `openspec` публикует `dist/`, `bin/` и `schemas/`. Инструменты сборки и тестирования (vite, rollup, vitest, eslint и их транзитивные зависимости) не публикуются. Сканеры, читающие `pnpm-lock.yaml` без разделения областей зависимостей, сообщают об уязвимостях пакетов, которые не попадают в установленный OpenSpec.

Это можно проверить самостоятельно: установите пакет и посмотрите содержимое.

```sh
npm install @fission-ai/openspec
ls node_modules | grep -E '^(vite|rollup|vitest|eslint|js-yaml|minimatch)$'   # совпадений нет
```

`pnpm audit --prod` в этом репозитории проверяет ту же область. CI выполняет проверку для каждого pull request.

<a id="what-the-cli-does-on-your-machine"></a>
## Что CLI делает на вашем компьютере

| Область | Поведение |
| --- | --- |
| Скрипты установки | В пакете нет скриптов `preinstall`, `install` и `postinstall`, поэтому установка из npm не выполняет код OpenSpec. `prepare` объявлен, но npm запускает его только при установке из Git или локального каталога для сборки исходников. Дополнения команд включаются по желанию через `openspec completion install`; при первом запуске CLI выводит краткую подсказку. |
| Запуск других программ | Вызовы через оболочку используют фиксированные строки (`which gh`, `gh auth status`). Ваши данные, включая текст issue, пути редактора, команды рабочего набора и путь для `openspec update`, передаются массивом аргументов без подстановки в строку оболочки. На Windows обёртки `.cmd` запускаются через `cross-spawn`, экранирующий аргументы вместо их склеивания. |
| Установка программ | `openspec update` может выполнить `npm install -g @fission-ai/openspec@latest`, затем повторно запустить `openspec update` обновлённым CLI. Это происходит только после положительного ответа, только для самого OpenSpec, только при установке через npm и никогда в CI или неинтерактивной оболочке. Глобальная установка находится вне проекта, использует ваши права и выполняет lifecycle-скрипты опубликованного пакета. После этого CLI считывает версию установленного файла и проверяет результат обновления. При отказе выводится команда для самостоятельного выполнения. |
| Телеметрия | Имя команды, версия OpenSpec и случайный UUID, созданный локально. Пути, содержимое файлов, окружение и имя компьютера не передаются; сбор IP явно отключён. Отключение: `OPENSPEC_TELEMETRY=0` или `DO_NOT_TRACK=1`. В CI телеметрия отключается автоматически. |
| Сеть | При включённой телеметрии отправляются её данные. Во время `openspec update` выполняется один запрос в npm для проверки новой версии CLI. Он не передаёт сведений о вас сверх обычного HTTP-запроса, выполняется один раз за вызов без кеширования и пропускается, если `CI` имеет любое значение, кроме явно выключающего, задано `NODE_ENV=test`, установлено `OPENSPEC_NO_UPDATE_CHECK`, `DO_NOT_TRACK=1` или `OPENSPEC_TELEMETRY=0`. Чтение, запись и проверка спецификаций выполняются полностью локально. |

<a id="automated-checks"></a>
## Автоматические проверки

| Инструмент | Область проверки |
| --- | --- |
| [CodeQL (английский)](https://github.com/Fission-AI/OpenSpec/security/code-scanning) | Статический анализ каждого push и pull request в `main` |
| [Dependabot (английский)](https://github.com/Fission-AI/OpenSpec/security/dependabot) | Уведомления об уязвимостях зависимостей и еженедельные PR обновления CLI, сайта документации и действий CI |
| Проверка зависимостей | Блокирует pull request, добавляющий зависимость с уязвимостью высокой серьёзности |
| Сканирование секретов | Включено для репозитория, включая защиту при push |
| `pnpm audit` | Опубликованные зависимости проверяются в каждом PR, при push в `main` и еженедельно. В PR результат рекомендательный, чтобы не блокировать несвязанные изменения; в остальных запусках ошибки останавливают проверку, поэтому новые уведомления видны и без изменения зависимостей. Проверка инструментов сборки всегда рекомендательная. |
| Закреплённые действия | Каждое действие GitHub запускается по SHA коммита; перемещение тега не меняет код, выполняемый в CI |

Уведомления оцениваются по модели угроз выше. Поэтому уязвимости инструментов, используемых только при сборке, исправляются в обычном цикле обновлений и не рассматриваются как инцидент.
