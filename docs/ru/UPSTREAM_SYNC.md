# Обновите проект из исходного репозитория

Принимайте изменения Fission-AI/OpenSpec обычным слиянием Git. Переводы в `docs/ru/` остаются отдельными файлами, а история обеих веток сохраняется.

## Проверьте рабочее дерево

В терминале из корня проекта:

```bash
git status --short
git remote -v
```

Первая команда должна вывести пустой результат. Если есть изменения, сначала сохраните их коммитом или отложите. Выполняйте слияние в той локальной ветке форка, которую собираетесь обновлять.

`origin` обычно указывает на ваш форк. Проверьте адрес до получения обновлений.

## Подключите исходный репозиторий

Если remote с именем `upstream` отсутствует, в терминале:

```bash
git remote add upstream https://github.com/Fission-AI/OpenSpec.git
```

Если `upstream` уже существует, проверьте его адрес через `git remote -v`. Продолжайте, только если он указывает на Fission-AI/OpenSpec. Не заменяйте существующий remote с другим назначением автоматически.

## Получите и просмотрите обновления

В терминале:

```bash
git fetch upstream
git remote set-head upstream --auto
git log --oneline HEAD..upstream/HEAD
git diff --stat HEAD...upstream/HEAD
```

`upstream/HEAD` указывает на основную ветку исходного проекта. Команда `set-head` определяет её по remote, поэтому инструкция не зависит от имени `main` или `master`. Если определить основную ветку не удалось, уточните нужную ветку до слияния.

Последние две команды показывают новые коммиты и объём изменений. Они не меняют рабочие файлы.

## Выполните слияние

В терминале:

```bash
git merge upstream/HEAD
```

Git либо завершит слияние, либо перечислит конфликты. Отсутствие конфликтов заранее не гарантируется.

**Конфликт в основном README:** сохраните новую английскую версию и один блок между `<!-- russian-docs:start -->` и `<!-- russian-docs:end -->`. Проверьте ссылку на `docs/ru/README.md` и путь к изображению кнопки.

**Конфликт оригинальной документации:** сверяйте его с исходным проектом. Русский текст добавляйте в `docs/ru/`, а английский оригинал сохраняйте на прежнем пути.

После разрешения конфликтов добавьте исправленные файлы через `git add` и завершите слияние командой `git commit`. Если требуется отменить ещё не завершённое слияние с конфликтами, выполните `git merge --abort`.

Не используйте `reset --hard`, пересоздание репозитория или принудительную отправку ради добавления перевода.

## Сверьте перевод после обновления

Отдельным коммитом обновите русскую документацию:

1. Найдите новые, изменённые, переименованные и удалённые оригиналы в областях из [правил перевода](TRANSLATION_RULES.md).
2. Сравните каждый изменённый оригинал с версией, по которой проверен его перевод.
3. Обновите русский текст, примеры, ссылки и якоря. Исчезнувшие источники разбирайте по одному; не удаляйте переводы автоматически.
4. После сверки запишите проверенную версию оригинала и состояние страницы в реестр.

Реестр находится в `docs/ru/translation-manifest.json`. Для каждого оригинала он хранит путь перевода, проверенный коммит, Git blob и состояние страницы. Проверяйте изменения из корня проекта:

```bash
node scripts/check-russian-docs.mjs
node scripts/check-russian-docs.mjs --json
```

Команды ничего не записывают и не обращаются к сети. Отчёт показывает новые источники (`uncovered`), отсутствующие переводы (`missing-translation`), черновики (`draft`), изменённые оригиналы (`stale`), исчезнувшие источники (`missing-source`), незавершённые оригиналы (`source-incomplete`) ошибки ссылок (`broken-link`) и переходы, потерявшие русскую версию (`untranslated-link`).

После сверки страницы обновите её запись в реестре. Полный коммит и blob можно узнать командами:

```bash
git rev-parse HEAD
git rev-parse HEAD:docs-lab/start/installation.md
```

Во второй команде подставьте путь нужного оригинала. Используйте коммит, в котором уже сохранены проверенные изменения оригинала. Убедитесь, что текст страницы, ссылка на версию и запись реестра относятся к одному состоянию.

Перед объявлением всего комплекта готовым выполните:

```bash
node scripts/check-russian-docs.mjs --strict
```

Строгая проверка возвращает ненулевой код при любом замечании, включая незавершённые страницы upstream. Сам факт перевода заголовков не делает такое руководство готовым.

Проверке нужны коммиты, записанные в реестре. Если репозиторий клонирован с ограничением глубины и нужная версия недоступна, получите полную историю из своего `origin` через `git fetch --unshallow origin`, затем повторите проверку.

Тесты самой проверки:

```bash
node --test scripts/check-russian-docs.test.mjs
```

Отдельный процесс CI `.github/workflows/russian-docs.yml` запускает тесты и проверяет комплект на Windows, macOS и Linux. Он сообщает о незавершённых оригиналах, а ошибки перевода, версий и ссылок останавливают проверку. Обязательный запуск `--strict` для полной готовности возможен после завершения исходных страниц. Для проверки версий CI загружает полную историю Git.

После слияния проверьте, что кнопка README открывает русский раздел. Пока все страницы не переведены и не сверены, сохраняйте на русской главной странице отметку о неполноте.
