# Обновите проект из исходного репозитория

Принимайте изменения Fission-AI/OpenSpec обычным слиянием Git. Переводы хранятся отдельно в `docs/ru/` и сверяются после обновления английских оригиналов.

## Проверьте рабочее дерево и remote

В терминале из корня проекта:

```bash
git status --short
git remote -v
```

Перед слиянием сохраните незавершённую работу коммитом или отложите её. `origin` должен указывать на ваш форк, `upstream` на `https://github.com/Fission-AI/OpenSpec.git`.

Если `upstream` отсутствует, добавьте его:

```bash
git remote add upstream https://github.com/Fission-AI/OpenSpec.git
```

Если имя уже занято другим репозиторием, сначала выясните его назначение. Не заменяйте существующий remote автоматически.

## Получите обновления

В терминале:

```bash
git fetch upstream
git remote set-head upstream --auto
git log --oneline HEAD..upstream/HEAD
git diff --stat HEAD...upstream/HEAD
```

`upstream/HEAD` указывает на основную ветку исходного проекта. Если определить её не удалось, уточните целевую ветку перед слиянием.

## Слейте изменения

В обновляемой локальной ветке форка:

```bash
git merge upstream/HEAD
```

Git завершит слияние либо перечислит конфликты. Если конфликтует README, сохраните новую английскую версию и один блок между `<!-- russian-docs:start -->` и `<!-- russian-docs:end -->`. Проверьте путь кнопки и переход в `docs/ru/README.md`.

После разрешения конфликтов добавьте исправленные файлы через `git add` и завершите слияние командой `git commit`. Незавершённое слияние с конфликтами можно отменить через `git merge --abort`.

Обычное слияние сохраняет обе истории. Для русификации не нужны пересоздание репозитория, `reset --hard` или принудительная отправка.

## Обновите перевод отдельным коммитом

1. Найдите новые, изменённые и исчезнувшие источники в согласованных областях из [технического решения](../../openspec/changes/archive/2026-10-27-add-russian-documentation/design.md).
2. Сравните изменённые страницы с проверенными версиями их переводов.
3. Обновите русский текст, примеры, ссылки и якоря.
4. После сверки запишите проверенную версию оригинала. Переименованные и удалённые страницы разбирайте по одной, сохраняя перевод до решения по конкретной записи.

Реестр находится в [translation-manifest.json](translation-manifest.json). Дата изменения русского файла сама по себе не подтверждает актуальность.

## Запустите проверку

Из корня репозитория, с Node.js 20.19.0 или новее:

```bash
node scripts/check-russian-docs.mjs
node scripts/check-russian-docs.mjs --json
node scripts/check-russian-docs.mjs --strict
node --test scripts/check-russian-docs.test.mjs
```

Проверка читает рабочее дерево, реестр и историю Git. Она не обращается к сети и не записывает файлы. Обычный отчёт возвращает код 0 при замечаниях к документации; неверный реестр возвращает 1. `--strict` возвращает 1 при блокирующих ошибках и 0, если есть только допустимые предупреждения или замечаний нет. Неизвестный параметр возвращает 2.

Для приёмки вручную запустите `--strict` и локальные тесты. В JSON-отчёте допустимые предупреждения имеют `severity: "warning"`; записи без этого поля считаются ошибками.

| Замечание | Действие |
|---|---|
| `uncovered` | Добавьте точную пару нового источника и перевода в реестр |
| `stale` | Сверьте изменённый оригинал с переводом |
| `missing-source` | Проверьте удаление или переименование; сохраните перевод до решения по записи |
| `missing-translation` | Восстановите или создайте соответствующий русский файл |
| `pending`, `draft` | Завершите перевод и сверку |
| `source-incomplete` | Допустимое предупреждение: весь доступный текст переведён, статус записан в реестре, на странице сохранена видимая пометка |
| `missing-source-notice` | Добавьте на страницу видимую пометку «Оригинал этой страницы ещё не завершён.» |
| `unmarked-source-incomplete` | Укажите `source-incomplete` для обнаруженного незавершённого оригинала и сохраните пометку на странице |
| `invalid-manifest` | Исправьте формат, дубликаты, пути или проверенные SHA |
| `untranslated-link` | Добавьте переход в русский файл вместо английского |
| `broken-link`, `broken-anchor` | Исправьте путь, регистр или якорь |

Тесты создают временные Git-репозитории с пробелами в пути. Они проверяют изменения, новые страницы, переименование, удаление, CRLF и слияние с конфликтом README. Дополнительные сценарии проверяют приёмку явно помеченного незавершённого оригинала и отказ при скрытой пометке, отставании или других ошибках.

Приёмка выполняется вручную. Явно помеченные незавершённые оригиналы сами по себе не блокируют её; остальные ошибки должны быть устранены. Фактические результаты и среда запуска находятся в [VALIDATION.md](VALIDATION.md).

## Обновите проверенную версию

Сравните оригинал с `sourceCommit` из конкретной записи, затем исправьте перевод. Для примера с `docs-lab/start/setup.md` после сверки получите значения:

```bash
git rev-parse HEAD
git rev-parse HEAD:docs-lab/start/setup.md
```

Первое значение запишите в `sourceCommit`, второе в `sourceBlob` соответствующей записи. Обновите ссылку на проверенную версию в начале русского файла. Установите `reviewed` для полного оригинала либо `source-incomplete` для незавершённого. Для нового непроверенного перевода используйте `pending` или `draft`; оба SHA могут быть `null`.

Повторите проверку, изучите diff и оформите обновление перевода отдельным коммитом после слияния исходных страниц. Не меняйте SHA остальных записей, если их перевод не сверялся.

При ошибке отсутствующей версии сначала проверьте SHA. Если история клонирована не полностью, получите её из соответствующего remote через `git fetch --unshallow origin` (только для shallow-клона). Для проверки нужна история, содержащая коммиты, указанные в реестре.
