# Глоссарий

> Каждый термин OpenSpec с определением в одну строку.

OpenSpec использует слова, которые в Git, CI и инструментах агентов могут означать другое. В каждой строке дано значение OpenSpec. Последний столбец ведёт к подробностям, если они есть.

| Термин | Определение | Подробнее |
|---|---|---|
| **Реализация (Apply)** | Выполнение задач предложения. Навык: `openspec-apply-change`. | [Реализация изменения](skills.md#openspec-apply-change) |
| **Архивирование (Archive)** | Завершение предложения: перенос его требований в основные спецификации и папки в `openspec/changes/archive/`. | [Быстрый старт](../start/quickstart.md) |
| **Артефакт (Artifact)** | Документ планирования внутри предложения: `proposal.md`, изменения спецификаций, `design.md`, `tasks.md`. Это не результат сборки. | [Артефакты](schemas/spec-driven/index.md#artifacts) |
| **Возможность продукта (Capability)** | Одна область поведения системы. У каждой своя спецификация в `openspec/specs/<capability>/spec.md`. | [Возможности продукта](schemas/spec-driven/index.md#proposalmd) |
| **Предложение по изменению (Change proposal)** | Единица работы: папка `openspec/changes/<name>/` с артефактами планирования. Часто сокращается до «изменение». Это не коммит Git. | [Предложение](../start/quickstart.md#step-2-propose) |
| **Команда (Command)** | Вводимая вручную точка входа в процесс. Написание зависит от инструмента (`/opsx:propose`, `/opsx-propose`). В документации процессы называются по навыкам. | [Поддерживаемые инструменты](supported-tools.md) |
| **Продолжение (Continue)** | Создание следующего артефакта существующего предложения. Навык: `openspec-continue-change`. | [Навыки](skills.md) |
| **Форма установки (Delivery)** | Как устанавливаются процессы: навыки, команды или обе формы. | [Настройка проекта](../start/setup.md) |
| **Изменения спецификации (Delta spec)** | Спецификация внутри предложения, содержащая только изменения под заголовками `ADDED`, `MODIFIED`, `REMOVED`, `RENAMED`. | [Изменения спецификаций](schemas/spec-driven/index.md#delta-specs-specmd) |
| **Исследование (Explore)** | Обдумывание идеи с агентом до подготовки предложения. Код не записывается. Навык: `openspec-explore`. | [Исследование идеи](skills.md#openspec-explore) |
| **Ускоренное планирование (Fast-forward)** | Создание предложения со всеми артефактами за один проход, до готовности к реализации. Навык: `openspec-ff-change`. Это не fast-forward в Git. | [Навыки](skills.md) |
| **Прежний процесс (Legacy workflow)** | Команды `/openspec:*`, использовавшиеся до OPSX. | |
| **Цикл (Loop)** | Путь предложения: исследование, предложение, проверка, реализация, архивирование. | [Быстрый старт](../start/quickstart.md) |
| **Основные спецификации (Main specs)** | Дерево `openspec/specs/`: текущее согласованное поведение системы. Архивирование переносит сюда изменения требований. Для возможности без спецификации она создаётся из требований `ADDED`. | [Архивирование](../start/quickstart.md#step-5-archive) |
| **Корень OpenSpec (OpenSpec root)** | Дерево `openspec/`, выбранное командой для работы: в вашем репозитории или в хранилище. | [Хранилища](../multi-repo/stores.md#where-artifacts-get-created-when-using-stores) |
| **OPSX** | Текущая система рабочих процессов OpenSpec и устанавливаемый префикс команд (`/opsx:`). | |
| **Профиль (Profile)** | Набор процессов, устанавливаемых init: `core` или `custom`. | [Профили](../customize/profiles.md) |
| **Подготовка предложения (Propose)** | Создание предложения со всеми артефактами за один шаг. Навык: `openspec-propose`. | [Быстрый старт](../start/quickstart.md) |
| **Реестр (Registry)** | Список зарегистрированных хранилищ на компьютере в `registry.yaml`. Это не реестр пакетов. | [CLI](cli.md#openspec-store) |
| **Требование (Requirement)** | Обязательное поведение системы, записанное с SHALL под `### Requirement:` в спецификации. | [Изменения спецификаций](schemas/spec-driven/index.md#delta-specs-specmd) |
| **Сценарий (Scenario)** | Проверяемый пример требования в форме WHEN/THEN. | [Изменения спецификаций](schemas/spec-driven/index.md#delta-specs-specmd) |
| **Схема (Schema)** | Определение артефактов предложения и порядка их подготовки. Это не JSON Schema. | [Схемы](schemas/index.md) |
| **Навык (Skill)** | Инструкции процесса, установленные там, где их читает ИИ-инструмент (`.agents/skills/` и т. п.). | [Навыки](skills.md) |
| **Спецификация (Spec)** | Файл текущего поведения одной возможности в `openspec/specs/<capability>/spec.md`. | [Архивирование](../start/quickstart.md#step-5-archive) |
| **spec-driven** | Схема по умолчанию: предложение, изменения спецификаций, техническое решение, задачи. | [spec-driven](schemas/spec-driven/index.md) |
| **Хранилище спецификаций (Store)** | Отдельный репозиторий OpenSpec, зарегистрированный на компьютере для планирования между репозиториями. Это не хранилище прикладных данных. | [Хранилища (beta)](../multi-repo/stores.md) |
| **Синхронизация (Sync)** | Перенос реализованных изменений требований в основные спецификации без архивирования. Навык: `openspec-sync-specs`. | [Навыки](skills.md) |
| **Шаблон (Template)** | Начальное содержимое, которое схема задаёт артефакту. | [Схемы](../customize/schemas.md) |
| **Обновление (Update)** | Навык `openspec-update-change` пересматривает артефакты предложения. Команда CLI `openspec update` обновляет установленные файлы OpenSpec. | [Обновление изменения](skills.md#openspec-update-change), [CLI](cli.md) |
| **Проверка (Verify)** | Сверка реализации с артефактами предложения перед архивированием. Навык: `openspec-verify-change`. | [Навыки](skills.md) |
| **Рабочий процесс (Workflow)** | Именованное действие OpenSpec (propose, apply, archive и т. п.), установленное в ИИ-инструмент как навык или команда. | [Настройка проекта](../start/setup.md) |
| **Рабочий набор (Workset)** | Личная локальная группа папок, открываемых вместе одним инструментом. Это не хранилище; данные не становятся общими. | [Рабочие наборы (beta)](../multi-repo/worksets.md) |
