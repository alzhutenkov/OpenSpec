<a id="set-up-your-project"></a>
# Настройте проект

> Добавьте OpenSpec в проект: выполните init, проверьте созданные файлы и настройте их.

<a id="pick-where-openspec-lives"></a>
## Выберите расположение OpenSpec

- **В вашем репозитории (по умолчанию):** спецификации и изменения находятся рядом с описываемым кодом и версионируются вместе с ним. Далее рассматривается этот вариант.
- **В хранилище:** отдельный репозиторий планирования, общий для нескольких репозиториев. Подходит для работы в нескольких репозиториях или полного отделения планов от кода. В [руководстве по хранилищам (beta)](../multi-repo/stores.md) описаны выбор и настройка.

<a id="initialize-your-project"></a>
## Инициализируйте проект

Установите CLI ([Установка](installation.md)), затем запустите init в корне проекта. В терминале:

```bash
cd <your-project>
openspec init
```

Init спросит, какими ИИ-инструментами вы пользуетесь, запишет файлы рабочих процессов для выбранных инструментов и сообщит результат:

```
OpenSpec Setup Complete

Created: Claude Code
6 skills and 6 commands in .claude/
Config: openspec/config.yaml (schema: spec-driven)
```

[Русское пояснение подписей и сообщений](../../EXAMPLE_NOTES.md#example-034).


Перезапустите IDE, чтобы новые команды стали доступны.

Init можно выполнять повторно:

- Для уже настроенных инструментов выводится `Refreshed` вместо `Created`.
- Повторный запуск с выбором нового инструмента добавляет его.
- Флаг `--tools` позволяет пропустить выбор в диалоге ([справочник CLI](../reference/cli.md)).

<a id="migrate-an-existing-projectmd"></a>
### Перенесите существующий `project.md`

Init не копирует старый `openspec/project.md` в `config.yaml`. Он сохраняет файл и выводит запрос на перенос с помощью ИИ.

В чате ИИ-помощника:

```
Просмотри openspec/project.md и перенеси полезное содержимое в openspec/config.yaml.
Оставь context кратким: только общие факты о проекте, нужные при создании артефактов, реализации и архивировании.
Указания для конкретных артефактов перенеси в rules соответствующих артефактов.
Указания для apply и archive перенеси в соответствующие записи operations.
Пропусти общие, устаревшие и многословные материалы. Не удаляй project.md.
```

Проверьте `config.yaml`, затем удалите `project.md`, когда будете готовы.

<a id="what-init-installs"></a>
## Что устанавливает init

Init создаёт в проекте два вида файлов:

- Папку `openspec/` в корне репозитория.
- Файлы рабочих процессов (навыки и команды) в папке вашего ИИ-инструмента (`.agents/`, `.claude/` и т. п.).

Добавляйте их в Git вместе с остальным кодом. Init больше ничего не меняет в репозитории. Если найдёт остатки прежней версии OpenSpec, спросит перед их очисткой.

<a id="the-openspec-folder"></a>
### Папка `openspec/`

Все артефакты OpenSpec находятся здесь, в корне проекта:

```
openspec/
├── config.yaml     настройки проекта и контекст для ИИ
├── specs/          ваши спецификации (пока пусто)
└── changes/        изменения в работе (пока пусто)
    └── archive/    сюда перемещаются завершённые изменения
```

Файл `config.yaml` описан в [настройках проекта](../customize/project-config.md).

<a id="the-workflow-files-skills-and-commands"></a>
### Файлы рабочих процессов (навыки и команды)

Это действия OpenSpec, которыми вы пользуетесь в работе. Так выглядят установленные навыки в общей папке `.agents/`, которую используют большинство инструментов:

```
.agents/skills/
├── openspec-explore/              обдумать идею
├── openspec-propose/              предложить изменение
├── openspec-apply-change/         выполнить задачи изменения
├── openspec-update-change/        пересмотреть план изменения
├── openspec-sync-specs/           перенести требования изменения в specs/
├── openspec-archive-change/       отправить завершённое изменение в архив
├── openspec-verify-change/        проверить соответствие реализации плану (по умолчанию не включён)
└── openspec-bulk-archive-change/  архивировать несколько изменений (по умолчанию не включён)
```

Здесь показан набор по умолчанию и два дополнительных процесса. Все двенадцать перечислены в [профилях](../customize/profiles.md).

По умолчанию каждый процесс устанавливается в двух формах:

- **Навык** (`openspec-apply-change`): инструкции, которые агент подхватывает сам, когда вы просите выполнить работу.
- **Команда** (`/opsx:apply` в Claude Code): вводимая вручную точка входа в тот же процесс с коротким именем.

Функционально они одинаковы. Навык и команда одного процесса содержат одни инструкции.

Причина двух форм: команды появились раньше, и каждый инструмент записывает их по-своему. Навыки являются новым общим стандартом, но не каждый инструмент может вызывать их напрямую. Для таких инструментов команды остаются точкой входа.

Некоторые инструменты устанавливают только навыки. Если инструмент запускает навыки напрямую, init пропускает команды и сообщает об этом: `Commands skipped for: codex (uses skills)`.

Мы предпочитаем навыки и со временем планируем отказаться от команд.

<a id="change-what-gets-installed"></a>
#### Измените состав установки

Интерактивный выбор меняет форму установки и набор процессов ([Профили](../customize/profiles.md)). В терминале:

```bash
openspec config profile
```

Пример переключения только на навыки:

```
Current profile settings
  Delivery: both

? What do you want to configure? Delivery only
? Delivery mode (how workflows are installed): Skills only

Config changes:
  delivery: both -> skills
? Apply changes to this project now? (Y/n) y
```

[Русское пояснение подписей и сообщений](../../EXAMPLE_NOTES.md#example-002).


Ответ «да» сразу применяет настройку к текущему проекту. Остальные проекты подхватят её при следующем `openspec update`. Настройка глобальная для компьютера.

<a id="claude-code-doesnt-show-the-workflows"></a>
#### Claude Code не показывает рабочие процессы

Claude Code загружает процессы OpenSpec из одного или обоих путей проекта в зависимости от настройки delivery:

- **Навыки:** `.claude/skills/openspec-*/SKILL.md`.
- **Команды:** `.claude/commands/opsx/<id>.md`.

Если файлов нет, обновите проект. В терминале:

```bash
openspec update
```

Если файлы команд есть, но `/opsx:` не показывает команды OpenSpec, обновите и перезапустите Claude Code. Если команды всё ещё не загружаются, включите также навыки. В терминале:

```bash
openspec config set delivery both
openspec update
```

Перезапустите Claude Code и выполните `/openspec-propose` в его чате. Если отсутствует только часть процессов, [измените профиль](../customize/profiles.md#expanding-the-set-optional-workflows).

Настройка завершена. [Быстрый старт](quickstart.md) проведёт вас через первое изменение.
