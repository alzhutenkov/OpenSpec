<a id="set-up-your-project"></a>
# Настройте проект

> Добавьте OpenSpec в проект: выполните init, изучите созданные файлы и настройте их.

<a id="pick-where-openspec-lives"></a>
## Выберите, где хранить OpenSpec

- **В репозитории (по умолчанию)**: спецификации и изменения располагаются рядом с описываемым кодом и версионируются вместе с ним. Далее описан этот вариант.
- **В хранилище**: отдельный репозиторий планирования, общий для нескольких репозиториев. Подходит для работы с несколькими репозиториями или для хранения планов отдельно от кода. В разделе [Хранилища (beta)](../multi-repo/stores.md) описаны выбор этого варианта и настройка.

<a id="initialize-your-project"></a>
## Инициализируйте проект

После [установки CLI](installation.md) выполните init в корне проекта. В терминале:

```bash
cd <your-project>
openspec init
```

Init спрашивает, какие ИИ-инструменты вы используете, записывает файлы выбранных рабочих процессов и показывает результат:

```
OpenSpec Setup Complete

Created: Claude Code
6 skills and 6 commands in .claude/
Config: openspec/config.yaml (schema: spec-driven)
```

[Русское пояснение подписей и сообщений](../../EXAMPLE_NOTES.md#example-034).


Перезапустите IDE, чтобы стали доступны новые команды.

Повторный запуск init безопасен:

- Для уже настроенных инструментов выводится `Refreshed` вместо `Created`.
- Выбор нового инструмента при повторном запуске добавляет его.
- Флаг `--tools` пропускает интерактивный выбор ([справочник CLI](../reference/cli.md)).

<a id="migrate-an-existing-projectmd"></a>
### Перенесите существующий `project.md`

Init не копирует прежний `openspec/project.md` в `config.yaml`. Он сохраняет файл и выводит запрос для переноса с помощью ИИ.

В чате ИИ-помощника:

```
Изучите openspec/project.md и перенесите полезное содержимое в openspec/config.yaml.
Сохраните context кратким: только общие факты проекта, необходимые при создании артефактов, apply и archive.
Перенесите указания для отдельных артефактов в rules соответствующих артефактов.
Перенесите указания для apply или archive в соответствующую запись operations.
Исключите общие, устаревшие и многословные материалы. Не удаляйте project.md.
```

Проверьте `config.yaml`, затем удалите `project.md`, когда будете готовы.

<a id="what-init-installs"></a>
## Что устанавливает init

Init создаёт в проекте:

- Каталог `openspec/` в корне репозитория.
- Файлы рабочих процессов (навыки и команды) в каталоге ИИ-инструмента (`.agents/`, `.claude/` и т. п.).

Добавьте всё это в Git вместе с исходным кодом. Другие файлы репозитория init не меняет. Если обнаружены следы старой версии OpenSpec, перед их очисткой запрашивается разрешение.

<a id="the-openspec-folder"></a>
### Каталог `openspec/`

Все артефакты OpenSpec находятся в этом каталоге в корне проекта:

```
openspec/
├── config.yaml     настройки проекта и контекст для ИИ
├── specs/          спецификации (пока пусто)
└── changes/        изменения в работе (пока пусто)
    └── archive/    сюда перемещаются завершённые изменения
```

Файл `config.yaml` описан в [конфигурации проекта](../customize/project-config.md).

<a id="the-workflow-files-skills-and-commands"></a>
### Файлы рабочих процессов (навыки и команды)

Это действия OpenSpec, которыми вы пользуетесь во время работы. Ниже показаны установленные навыки в общем каталоге `.agents/`, который использует большинство инструментов:

```
.agents/skills/
├── openspec-explore/              обдумать идею
├── openspec-propose/              предложить изменение
├── openspec-apply-change/         выполнить задачи изменения
├── openspec-update-change/        пересмотреть план изменения
├── openspec-sync-specs/           перенести обновления спецификаций в specs/
├── openspec-archive-change/       переместить завершённое изменение в архив
├── openspec-verify-change/        проверить соответствие реализации плану (не входит в набор по умолчанию)
└── openspec-bulk-archive-change/  архивировать несколько изменений (не входит в набор по умолчанию)
```

Здесь показан набор по умолчанию и два дополнительных процесса. Все двенадцать перечислены в разделе [Профили](../customize/profiles.md).

По умолчанию каждый рабочий процесс устанавливается в двух формах:

- **Навык** (`openspec-apply-change`): инструкции, которые агент подхватывает самостоятельно, когда вы просите выполнить работу.
- **Команда** (`/opsx:apply` в Claude Code): явно вводимая точка входа в тот же процесс с коротким именем.

Они функционально одинаковы. Навык и команда одного процесса содержат одинаковые инструкции.

Команды появились раньше, и каждый инструмент использует своё написание. Навыки стали общим стандартом, но не каждый инструмент умеет вызывать их напрямую. Для таких инструментов команды остаются точкой входа.

Некоторые инструменты устанавливают только навыки. Если инструмент выполняет навыки напрямую, init пропускает команды и сообщает об этом: `Commands skipped for: codex (uses skills)`.

Проект предпочитает навыки и со временем планирует отказаться от команд.

<a id="change-what-gets-installed"></a>
#### Измените устанавливаемый набор

Интерактивный выбор меняет форму установки и набор рабочих процессов ([Профили](../customize/profiles.md)). В терминале:

```bash
openspec config profile
```

Пример переключения на установку только навыков:

```
Current profile settings
  Delivery: both

? What do you want to configure? Delivery only
? Delivery mode (how workflows are installed): Skills only

Config changes:
  delivery: both -> skills
? Apply changes to this project now? (Y/n) y
```

[Русское пояснение подписей и сообщений](../../EXAMPLE_NOTES.md#example-002).


Ответ «да» сразу применяет настройку к текущему проекту. Другие проекты получат её при следующем `openspec update`. Настройка глобальная для компьютера.

<a id="claude-code-doesnt-show-the-workflows"></a>
#### Claude Code не показывает рабочие процессы

В зависимости от формы установки Claude Code загружает процессы из одного или обоих путей проекта:

- **Навыки**: `.claude/skills/openspec-*/SKILL.md`.
- **Команды**: `.claude/commands/opsx/<id>.md`.

Если файлов нет, обновите проект. В терминале:

```bash
openspec update
```

Если файлы команд существуют, но `/opsx:` не показывает команды OpenSpec, обновите Claude Code и перезапустите его. Если команды всё ещё не загружаются, включите также навыки. В терминале:

```bash
openspec config set delivery both
openspec update
```

Перезапустите Claude Code и выполните `/openspec-propose` в чате. Если не хватает отдельных процессов, [измените профиль](../customize/profiles.md#expanding-the-set-optional-workflows).

Настройка завершена. Раздел [Быстрый старт](quickstart.md) проведёт вас через первое изменение.
