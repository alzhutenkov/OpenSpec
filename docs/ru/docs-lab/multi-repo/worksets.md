# Рабочие наборы (beta)

> Откройте хранилище и использующие его репозитории в одном окне редактора, чтобы агент видел оба.

При использовании хранилища нужный агенту контекст распределён по папкам. Спецификации и изменения лежат в хранилище, код находится в отдельных репозиториях. Агент, запущенный в одном репозитории, может читать и искать только в нём, поэтому видит лишь часть картины.

Для этого OpenSpec предлагает рабочие наборы: сохранённые именованные списки папок, открываемых вместе. Здесь предполагается, что хранилище уже настроено и зарегистрировано на компьютере. Это описано в [руководстве по хранилищам (beta)](stores.md).

<a id="how-it-works"></a>
## Как это работает

- **Что это:** именованный список папок, сохранённый только на вашем компьютере. В папки участников ничего не записывается; в Git ничего не добавляется.
- **Что происходит при открытии:** OpenSpec создаёт файл `.code-workspace` из списка и запускает с ним редактор. Все папки набора оказываются в одном окне.
- **Что вы получаете:** поиск редактора и запущенный в окне агент могут читать все папки набора. Агент может искать по спецификациям хранилища и коду репозитория в одном сеансе.
- **Что не меняется:** выбор папки `openspec/` для команды. Он по-прежнему определяется правилами [расположения артефактов](stores.md#where-artifacts-get-created-when-using-stores).

<a id="set-it-up"></a>
## Настройте набор

1. **Сохраните рабочий набор** один раз на компьютер. Укажите репозиторий и хранилище как участников, а также инструмент открытия:

   ```bash
   # сохранить именованный список папок для совместного открытия
   openspec workset create platform \
     --member ~/src/web-app \
     --member ~/openspec/team-plans \
     --tool code
   ```

   ```yaml
   Saved workset 'platform' (2 members) to your machine.
   Open it any time with: openspec workset open platform
   ```

[Русское пояснение подписей и сообщений](../../../../openspec/specs/russian-documentation/support/EXAMPLE_NOTES.md#example-009).


2. **Открывайте набор** перед работой:

   ```bash
   # открыть всех участников в одном окне VS Code
   openspec workset open platform
   ```

`openspec workset list` показывает сохранённые наборы. `openspec workset remove <name>` удаляет набор, не затрагивая папки участников:

```yaml
platform  (opens in VS Code)
  web-app     /Users/you/src/web-app
  team-plans  /Users/you/openspec/team-plans
```

<a id="use-it-one-change-two-folders"></a>
## Используйте набор: одно изменение, две папки

Допустим, изменение `add-login` находится в хранилище `team-plans`, а его код в `web-app`. Откройте набор `platform` и попросите агента реализовать изменение. В одном сеансе он сможет:

- прочитать `team-plans/openspec/changes/add-login/` и соседние спецификации;
- отредактировать код в `web-app/`;
- запускать команды `openspec` внутри `web-app`.

Без рабочего набора агент видит только папку, в которой запущен.

<a id="tools-out-of-the-box"></a>
## Доступные инструменты

- **VS Code** (`--tool code`) и **Cursor** (`--tool cursor`): встроенная поддержка. Каждый открывает одно окно со всеми папками набора.
- **Claude Code и Codex в терминале:** временно отключены как инструменты открытия наборов, пока этот процесс перерабатывается. `--tool claude` и `--tool codex` завершаются ошибкой с объяснением и рекомендацией VS Code или Cursor.
- **Другие редакторы:** добавьте их в ключ `openers` в [настройках CLI (config.json)](../reference/configuration/config-json.md).
