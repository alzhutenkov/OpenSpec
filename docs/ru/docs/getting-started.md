<a id="getting-started"></a>
# Начало работы

В этом руководстве объясняется, как работает OpenSpec после его установки и инициализации. Инструкции по установке см. в [основном файле README](../README.md#quick-start) или в [Руководстве по установке](installation.md). Впервые во всем наборе документации? [Домашняя страница документации](README.md) отображает все.

> **Где мне вводить эти команды?** В двух местах, и их путаница — самая распространенная ошибка на ранних этапах.
>
> — Команды `openspec ...` (например, `openspec init`) выполняются в вашем **терминале**.
> — Команды `/opsx:...` (например, `/opsx:propose`) запускаются в вашем **чате AI-помощника**, в том же окне, где вы просите его написать код.
>
> отдельного «интерактивного режима» для запуска не существует. Вы просто вводите косую черту в чате, и ваш помощник берет ее оттуда. Полное объяснение: [Как работают команды](how-commands-work.md).

<a id="your-first-five-minutes"></a>
## Ваши первые пять минут

Весь цикл, где каждый шаг помечен тем, где он происходит:

```text
ТЕРМИНАЛ $cur -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | ш
TERMINAL $ cd your-project && openspec init
AI ЧАТ /opsx:explore (необязательно: сначала подумайте)
ЧАТ ИИ /opsx:propose add-dark-mode (ИИ составляет проект плана, вы его просматриваете)
ЧАТ ИИ /opsx:apply (его строит ИИ)
AI CHAT /opsx:archive (спецификации обновлены, изменения удалены)
```

Два шага настройки терминала, после чего вы общаетесь в чате. (Windows, npm и другие способы установки описаны в разделе [Установка](installation.md).) Остальная часть этого руководства описывает, что делает каждый шаг и что вы увидите.

**Не хотите выполнять терминальную часть самостоятельно?** Вставьте [подсказку установки](installation.md#install-with-your-ai-assistant) в свой помощник, и он обработает обе строки, а затем сообщит о том, что создал.

> **Еще не знаете, что построить? Начните с `/opsx:explore`.** Это мыслящий партнер без каких-либо ставок, который читает вашу кодовую базу, взвешивает варианты и превращает нечеткую идею в конкретный план еще до того, как будет написан какой-либо код. Когда изображение прояснится, оно передается `/opsx:propose`. Это единственная лучшая привычка для работы с ИИ, который в противном случае с уверенностью создаст неправильную вещь. См. [Руководство по изучению](explore.md).

<a id="how-it-works"></a>
## Как это работает

OpenSpec помогает вам и вашему помощнику по программированию ИИ договориться о том, что создавать, прежде чем писать какой-либо код.

**Быстрый путь по умолчанию (основной профиль):**

```text
/opsx:explore ──► /opsx:propose ──► /opsx:apply ──► /opsx:sync ──► /opsx:archive
   (необязательно)
```

начните с `/opsx:explore`, когда вы уже знаете, что делать, или сразу переходите к `/opsx:propose`. Explore находится в профиле по умолчанию, поэтому он всегда доступен, когда вы этого захотите.

**Расширенный путь (выбор пользовательского рабочего процесса):**

```text
/opsx:new ──► /opsx:ff or /opsx:continue ──► /opsx:apply ──► /opsx:verify ──► /opsx:archive
```

глобальный профиль по умолчанию — `core`, который включает `propose`, `explore`, `apply`, `update`, `sync` и `archive`. Вы можете включить расширенные команды рабочего процесса с помощью `openspec config profile`, а затем `openspec update`.

<a id="what-openspec-creates"></a>
## Что создает OpenSpec

После запуска `openspec init` ваш проект имеет следующую структуру:

```
openspec/
├── specs/              # Источник истины (поведение вашей системы)
│   └── <domain>/
│       └── spec.md
├── changes/            # Предлагаемые обновления (одна папка на каждое изменение)
│   └── <change-name>/
│       ├── proposal.md
│       ├── design.md
│       ├── tasks.md
│       └── specs/      # Дельта-спецификации (что меняется)
│           └── <domain>/
│               └── spec.md
└── config.yaml         # Конфигурация проекта (необязательно)
```

**Два ключевых каталога:**

- **`specs/`** — Источник истины. Эти спецификации описывают, как ваша система ведет себя в настоящее время. Организовано по домену (например, `specs/auth/`, `specs/payments/`).

- **`changes/`** — Предлагаемые модификации. Каждое изменение получает собственную папку со всеми связанными артефактами. Когда изменение завершено, его спецификации сливаются в основной каталог `specs/`.

<a id="understanding-artifacts"></a>
## Понимание артефактов

Каждая папка изменений содержит артефакты, которые направляют работу:

|Артефакт|Назначение|
|----------|---------|
|`proposal.md`|«почему» и «что» — отражают намерение, масштаб и подход.|
|`specs/`|спецификации Delta, показывающие требования ADDED/MODIFIED/REMOVED.|
|`design.md`|«Как» — технический подход и архитектурные решения|
|`tasks.md`|Контрольный список реализации с флажками.|

**Артефакты дополняют друг друга:**

```
proposal ──► specs ──► design ──► tasks ──► implement
   ▲           ▲          ▲                    │
   └───────────┴──────────┴────────────────────┘
            update as you learn
```

Вы всегда можете вернуться и уточнить более ранние артефакты, узнав больше в ходе реализации.

<a id="how-delta-specs-work"></a>
## Как работают дельта-спецификации

Дельта-спецификации являются ключевой концепцией OpenSpec. Они показывают, что меняется по сравнению с вашими текущими спецификациями.

<a id="the-format"></a>
### Формат

В спецификациях Delta используются разделы для указания типа изменения:

```markdown
# Дельта для аутентификации

## ADDED Requirements

### Requirement: двухфакторная аутентификация.
Система MUST требует второй фактор при входе в систему.

#### Scenario: требуется OTP.
- GIVEN пользователь с включенной двухфакторной аутентификацией.
- WHEN пользователь отправляет действительные учетные данные.
- THEN представлен вызов OTP.

## MODIFIED Requirements

### Requirement: тайм-аут сеанса.
сеансы системы SHALL прекращаются после 30 минут бездействия.
(Раньше: 60 минут)

#### Scenario: тайм-аут простоя
- GIVEN сеанс с аутентификацией.
- WHEN Прошло 30 минут без активности.
- THEN сеанс признан недействительным.

## REMOVED Requirements

### Requirement: запомнить меня.
(устарело в пользу 2FA)
```

<a id="what-happens-on-archive"></a>
### Что происходит в архиве

При архивировании изменений:

1. требования **ADDED** добавлены к основной спецификации.
2. требования **MODIFIED** заменяют существующую версию.
3. требования **REMOVED** удалены из основной спецификации.

папка изменений перемещается в `openspec/changes/archive/` для истории аудита.

<a id="example-your-first-change"></a>
## Пример: ваше первое изменение

Давайте рассмотрим добавление темного режима в приложение.

<a id="1-start-the-change-default"></a>
### 1. Запустите изменение (по умолчанию).

```text
Вы: /opsx:propose add-dark-mode

AI: Создано openspec/changes/add-dark-mode/
     ✓ proposal.md — почему мы это делаем, что меняется
     ✓ specs/ — требования и сценарии
     ✓ design.md — технический подход
     ✓ tasks.md — контрольный список реализации
     Готово к внедрению!
```

Если вы включили расширенный профиль рабочего процесса, вы также можете сделать это в два этапа: `/opsx:new`, затем `/opsx:ff` (или `/opsx:continue` постепенно).

<a id="2-what-gets-created"></a>
### 2. Что создается

**proposal.md** — фиксирует намерение:

```markdown
# Предложение: добавить темный режим.

## намерение
пользователи запросили опцию темного режима, чтобы уменьшить нагрузку на глаза.
при использовании в ночное время.

## Область
- Добавить переключатель темы в настройках.
- Поддержка определения системных предпочтений.
- сохранение предпочтений в localStorage.

## Подход
используйте пользовательские свойства CSS для оформления тем в контексте React.
для управления состоянием.
```

**specs/ui/spec.md** — Delta показывает новые требования:

```markdown
# Дельта для пользовательского интерфейса.

## ADDED Requirements

### Requirement: выбор темы.
Система SHALL позволяет пользователям выбирать между светлыми и темными темами.

#### Scenario: ручное переключение
- GIVEN пользователь на любой странице.
- WHEN пользователь нажимает на переключатель темы.
- THEN тема сразу переключается
- AND предпочтение сохраняется между сеансами.

#### Scenario: Системные настройки.
- GIVEN пользователь без сохраненных настроек.
- WHEN приложение загружается
- THEN используется предпочтительная цветовая схема системы.
```

**tasks.md** — Контрольный список реализации:

```markdown
# Задачи

## 1. Инфраструктура темы.
- [ ] 1.1 Создание ThemeContext со светлым/темным состоянием.
- [ ] 1.2 Добавление пользовательских свойств CSS для цветов.
- [ ] 1.3 Реализовать сохранение localStorage.

## 2. Компоненты пользовательского интерфейса.
- [ ] 2.1 Создание компонента ThemeToggle
- [ ] 2.2 Добавить переключатель на страницу настроек.
- [ ] 2.3 Обновить заголовок, включив в него быстрое переключение.

## 3. Стиль
- [ ] 3.1 Определить цветовую палитру темной темы
- [ ] 3.2 Обновление компонентов для использования переменных CSS.
```

<a id="3-implement"></a>
### 3. Реализация

```
You: /opsx:apply

AI:  Working through tasks...
     ✓ 1.1 Created ThemeContext with light/dark state
     ✓ 1.2 Added CSS custom properties to globals.css
     ✓ 1.3 Implemented localStorage persistence
     ✓ 2.1 Created ThemeToggle component
     ...
     All tasks complete!
```

[Русское пояснение подписей и сообщений](../../../openspec/specs/russian-documentation/support/EXAMPLE_NOTES.md#example-048).


Если во время реализации вы обнаружите, что конструкция требует корректировки, просто обновите артефакт и продолжайте.

<a id="4-archive"></a>
### 4. Архив

```
You: /opsx:archive

AI:  Archiving add-dark-mode...
     ✓ Merged specs into openspec/specs/ui/spec.md
     ✓ Moved to openspec/changes/archive/2025-01-24-add-dark-mode/
     Done! Ready for the next feature.
```

[Русское пояснение подписей и сообщений](../../../openspec/specs/russian-documentation/support/EXAMPLE_NOTES.md#example-049).


Ваши дельта-спецификации теперь являются частью основных спецификаций, документирующих работу вашей системы.

<a id="verifying-and-reviewing"></a>
## Проверка и рассмотрение

используйте CLI, чтобы проверить изменения:

```bash
# список активных изменений.
openspec list

# просмотреть сведения об изменении.
openspec show add-dark-mode

# проверка форматирования спецификации.
openspec validate add-dark-mode

# Интерактивная панель управления.
openspec view
```
