# Установка

<a id="install"></a>
## Установить

OpenSpec — это один файл. Ему не нужен Node.js или что-то еще (в Alpine Linux сначала запустите `apk add libstdc++ libgcc`).

macOS и Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | sh
```

Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.ps1 | iex
```

Программа установки выбирает новейшую версию, все файлы которой прикреплены, и файл, подходящий для вашего компьютера, сверяет ее с `SHA256SUMS` версии и устанавливает ее в `~/.local/bin` (Windows: `%LOCALAPPDATA%\Programs\openspec`, добавлен к вашему пользователю `PATH`). Установите `OPENSPEC_INSTALL_DIR`, чтобы выбрать другую папку, или `OPENSPEC_VERSION=v1.15.0`, чтобы закрепить выпуск. Предпочитаете npm или другой менеджер пакетов? См. [Менеджеры пакетов](#package-managers).

Чтобы установить вручную, загрузите файл вашей платформы из [последней версии](https://github.com/Fission-AI/OpenSpec/releases/latest), переименуйте его в `openspec` (`openspec.exe` в Windows), сделайте его исполняемым в macOS и Linux (`chmod +x openspec`) и поместите его на свой `PATH`:

|Платформа|Файл|
|---|---|
|macOS 13+ (Apple Silicon/Intel)|`openspec-darwin-arm64` / `openspec-darwin-x64`|
|Linux (glibc 2.17+)|`openspec-linux-x64` / `openspec-linux-arm64`|
|Alpine 3.17+ (требуется `apk add libstdc++ libgcc`)|`openspec-linux-x64-musl` / `openspec-linux-arm64-musl`|
|Windows 10+|`openspec-windows-x64.exe` / `openspec-windows-arm64.exe`|

в macOS файл, загруженный с помощью браузера, блокируется до тех пор, пока вы не запустите `xattr -d com.apple.quarantine openspec`; сценарий установки позволяет избежать этого. В Windows SmartScreen может выдать предупреждение при первом запуске из Проводника.

<a id="package-managers"></a>
## Менеджеры пакетов

Для установки с помощью менеджера пакетов требуется **Node.js 20.19.0 или выше** (проверьте с помощью `node --version`).

<a id="npm"></a>
### НПМ

```bash
npm install -g @fission-ai/openspec@latest
```

<a id="pnpm"></a>
### пнпм

```bash
pnpm add -g @fission-ai/openspec@latest
```

<a id="yarn"></a>
### пряжа

```bash
yarn global add @fission-ai/openspec@latest
```

Yarn 2 и более поздние версии (Berry) удалили команду `global`. В этих версиях вместо этого установите OpenSpec с помощью npm, pnpm или Bun — глобальный CLI не должен использовать общий менеджер пакетов вашего проекта.

<a id="deno"></a>
### имя

Иногда у Deno возникают проблемы с анализом тега @latest, но мы можем указать версию при
первоначальной установке. Если это произойдет, вы можете попробовать изменить тег @latest на версию, например `@^1.3.1` .

```bash
deno install --global \
  --allow-read --allow-write --allow-env --allow-sys=cpus,homedir --allow-net=edge.openspec.dev \
  npm:@fission-ai/openspec@latest
# или
deno install --global \
  --allow-read --allow-write --allow-env --allow-sys=cpus,homedir --allow-net=edge.openspec.dev \
  npm:@fission-ai/openspec@^1.3.1
```

Примечание. Если ваши подкоманды запускают внешние инструменты, такие как редактирование конфигурации, обратная связь или открытие рабочего пространства, вам может потребоваться --allow-run=<program>. с ограниченной областью действия.

<a id="bun"></a>
### булочка

Bun может установить OpenSpec глобально, но OpenSpec в настоящее время работает на Node.js.
Вам по-прежнему потребуется Node.js 20.19.0 или более поздняя версия, доступная на `PATH` .

```bash
bun add -g @fission-ai/openspec@latest
```

<a id="nix"></a>
## Никс

Запустите OpenSpec напрямую без установки:

```bash
nix run github:Fission-AI/OpenSpec -- init
```

Или установите в свой профиль:

```bash
nix profile install github:Fission-AI/OpenSpec
```

Или добавьте в свою среду разработки в `flake.nix`:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    openspec.url = "github:Fission-AI/OpenSpec";
  };

  outputs = { nixpkgs, openspec, ... }: {
    devShells.x86_64-linux.default = nixpkgs.legacyPackages.x86_64-linux.mkShell {
      buildInputs = [ openspec.packages.x86_64-linux.default ];
    };
  };
}
```

<a id="switch-from-npm-to-the-standalone-install"></a>
## переключиться с npm на автономную установку.

Ваши настройки и проекты переносятся; меняется только программа.

1. Запустите `openspec install`. Он устанавливает автономную копию и печатает команду, которая удаляет вашу старую.
2. Запустите эту команду, например `npm uninstall -g @fission-ai/openspec` (Homebrew: `brew uninstall openspec`). До тех пор старая копия будет работать первой в вашем PATH.
3. В новом терминале запустите `openspec version`. Он должен напечатать `OpenSpec <version> (standalone)`. Если он называет менеджер пакетов, в вашем PATH все еще находится другая копия: `which -a openspec` (Windows: `where.exe openspec`) перечисляет их.

<a id="updating"></a>
## Обновление

обновите CLI, снова запустив [команду установки](#install) (с помощью менеджера пакетов: `npm install -g @fission-ai/openspec@latest` или его эквивалента pnpm/yarn/bun). Затем обновите сгенерированные файлы каждого проекта:

```bash
openspec update   # запуск внутри каждого проекта.
```

`openspec update` восстанавливает файлы навыков и команд для настроенных вами инструментов, поэтому ваши косые команды остаются актуальными в соответствии с установленной версией. Он также проверяет, была ли опубликована более новая версия CLI, и предлагает обновиться, поскольку обновление — это то, что в первую очередь делает новые рабочие процессы доступными — см. [Справочник по CLI](cli.md#openspec-update).

<a id="uninstalling"></a>
## Удаление

команды `openspec uninstall` нет, поскольку OpenSpec — это всего лишь одна программа плюс несколько файлов в вашем проекте. Его удаление выполняется вручную, и ничто здесь не затрагивает ваш исходный код.

**1. Удалите CLI.** Удалите файл, установленный установщиком: `~/.local/bin/openspec` или в Windows `%LOCALAPPDATA%\Programs\openspec\openspec.exe` (и эту папку у вашего пользователя `PATH`). Если вы установили с помощью менеджера пакетов:

```bash
npm uninstall -g @fission-ai/openspec   # или: pnpm rm -g / Yarn global удалить / Bun rm -g
```

автономный двоичный файл также сохраняет, когда этот каталог доступен для записи, копию своих встроенных схем в вашем каталоге данных OpenSpec (`~/.local/share/openspec/binary-schemas` в macOS и Linux, `%LOCALAPPDATA%\openspec\binary-schemas` в Windows), которую вы также можете удалить.

**2. Удалите OpenSpec из проекта (необязательно).** Удалите каталог `openspec/`, если вам больше не нужны его спецификации и изменения:

```bash
rm -rf openspec/
```

Подумайте, прежде чем сделать это: `openspec/specs/` и `openspec/changes/archive/` — это ваши записи о том, как ведет себя система и почему она изменилась. Если вам может понадобиться эта история, сохраните папку (или сохраните ее в git) даже после удаления.

**3. Удалите сгенерированные файлы инструментов AI (необязательно).** OpenSpec записывает файлы навыков и команд в каталоги для каждого инструмента, такие как `.claude/skills/openspec-*/`, `.cursor/commands/opsx-*` и т. д. Удалите навыки `openspec-*` и команды `opsx-*` для любых настроенных вами инструментов. Точные пути для каждого инструмента указаны в разделе [Поддерживаемые инструменты](supported-tools.md).

Если у вас также есть блоки маркеров OpenSpec в таких файлах, как `CLAUDE.md` или `AGENTS.md`, удалите эти блоки вручную; ваш собственный контент в этих файлах остается за вами.
