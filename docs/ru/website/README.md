# Сайт документации OpenSpec

Сайт маркетинга и документации для [OpenSpec (английский)](https://github.com/Fission-AI/OpenSpec), созданный с помощью [Fumadocs (английский)](https://fumadocs.dev) и [Next.js (английский)](https://nextjs.org). Он настроен как **статический экспорт**, поэтому его можно развернуть на страницах Cloudflare (или на любом статическом хосте) без сервера.

> **Страницы документации генерируются, а не создаются здесь.** Файлы `docs/*.md` репозитория являются единственным источником правды. `scripts/sync-docs.mjs` зеркалирует их в `content/docs/` (как `.md`) при каждой сборке, поэтому сайт автоматически обновляется — локально и в CI. Редактируйте `../docs`, а не `content/docs/`. Только маркетинговая целевая страница (`app/(home)/page.tsx`) написана вручную. См. раздел [Синхронизация документов](#keeping-docs-in-sync).

<a id="quick-start"></a>
## Быстрый старт

```bash
cd website
pnpm install
pnpm run dev      # http://localhost:3000
```

|Скрипт|Что он делает|
|--------|--------------|
|`pnpm run sync:docs`|Зеркально `../docs/*.md` в `content/docs/`|
|`pnpm run dev`|синхронизируйте документы, затем запустите сервер разработки с горячей перезагрузкой.|
|`pnpm run build`|синхронизируйте документы, затем создайте статический сайт в `out/`.|
|`pnpm run start`|обслуживать созданный каталог `out/` локально.|
|`pnpm run types:check`|синхронизируйте документы, создайте типы и запустите `tsc --noEmit`.|

`sync:docs` автоматически запускается внутри `dev`, `build` и `types:check`, поэтому вы редко вызываете его напрямую.

<a id="deploy-to-cloudflare-pages"></a>
## Развертывание на страницах Cloudflare

Этот сайт представляет собой чистый статический экспорт — `pnpm run build` записывает простой
HTML, CSS, JS, предварительно созданный поисковый индекс и `llms.txt` в `out/`
. Наведите Cloudflare Pages на этот каталог и используйте следующие настройки:

|Настройка|Значение|
|---------|-------|
|Корневой каталог.|`website`|
|команда сборки.|`pnpm run build`|
|создать выходной каталог.|`out`|
|версия узла.|`22`|

установите одну переменную среды, чтобы URL-адреса изображений
социальных сетей/Open Graph соответствовали вашему реальному домену:

|переменная|Пример|
|----------|---------|
|`NEXT_PUBLIC_SITE_URL`|`https://openspec.dev`|

Сам сайт не требует выполнения сервера. Небольшой Worker маршрутизации предоставляет доступ
к отдельному проекту Pages в `openspec.dev/docs` , в то время как
проект Astro Landing продолжает владеть остальной частью `openspec.dev` . Он также
маршрутизирует поддерживающие пути `/_next` , поиск, Open Graph, icon и `llms`
. Его исходный код и конфигурация Wrangler находятся в `cloudflare/router/` .

Бесплатный план Cloudflare не может переопределить заголовок Host или источник
DNS в правиле происхождения, поэтому вместо этого работник маршрутизации передает эти
пути в `openspec-docs.pages.dev` . Разверните изменения маршрутизации из `website/` с помощью:

```bash
npx wrangler deploy --config cloudflare/router/wrangler.jsonc
```

<a id="deploy-with-wrangler-optional"></a>
### Развертывание с помощью Wrangler (необязательно)

```bash
pnpm run build
npx wrangler pages deploy out --project-name openspec-docs
```

<a id="keeping-docs-in-sync"></a>
## Синхронизация документов

Страницы документа представляют собой **механическое зеркало** репозитория
`docs/*.md` . В `content/docs/` редактировать вручную нечего
— эти файлы генерируются и игнорируются git.

**Чтобы изменить содержимое страницы:** отредактируйте соответствующий файл в `../docs`
. Следующий `pnpm run build` /`pnpm run dev` восстанавливает из него сайт.

**Чтобы добавить, удалить, изменить порядок или повторно добавить страницу,
а также изменить ее раздел или значок на боковой панели:**
отредактируйте `docs.sync.config.mjs` . Этот манифест — единственное место, которое
решает, какие документы публиковаться и как они появляются. `scripts/sync-docs.mjs` тогда:

- заголовок каждой страницы извлекается из ведущего `# H1`, а описание — из его
  первый абзац и вставляет вступление Fumadocs (включая `githubSource`, поэтому
  ссылка «изменить эту страницу» открывает настоящий `docs/*.md`);
- перезаписывает внутренние ссылки `*.md` на их внутренние маршруты `/docs/...`;
- записывает каждую страницу как `.md` (Fumadocs анализирует `.md` как обычный Markdown, поэтому
  `<placeholders>` и `{braces}` в документации трактуются буквально и никогда
  сломать сборку);
- восстанавливает `content/docs/meta.json` и `content/docs/reference/meta.json`.

Поскольку документы являются источником, сайт не может отклоняться от
них: каждая сборка повторно отображает их перед выполнением статического экспорта.

<a id="automated-deploys"></a>
## Автоматическое развертывание

проект `openspec-docs` Cloudflare Pages напрямую подключен к `Fission-AI/OpenSpec` .
Cloudflare перестраивает и развертывает `main` при изменении `docs/**` или `website/**`
, а также создает предварительные развертывания для запросов на извлечение.

Как только сайт изменится, все — редактирование `docs/*.md` , объединенное с
`main` , повторно отражает и повторно развертывает без каких-либо действий вручную.

для проекта страниц, подключенных к Git, не требуется рабочий
процесс GitHub Actions, секреты развертывания или переменные репозитория. Cloudflare
сообщает о статусах производственной и предварительной сборки непосредственно в GitHub.

<a id="landing-page"></a>
### Целевая страница

текущая целевая страница [openspec.dev (английский)](https://openspec.dev) остается в отдельном проекте
Astro. Работник маршрутизации отправляет в этот проект Pages только
пути, принадлежащие документации, поэтому его целевая страница Fumadocs в
`app/(home)/page.tsx` создается, но не обслуживается в общедоступном корне. Позднее
проекты можно объединить без изменения рабочего процесса зеркальной документации.

<a id="project-structure"></a>
## Структура проекта.

```text
website/
├── app/                     # Маршрутизатор приложений Next.js
│   ├── (home)/page.tsx # целевая маркетинговая страница
│   ├── docs/                # макет документов + общая страница
│   ├── api/search/          # маршрут индекса статического поиска
│   ├── llms.txt / llms-full.txt / llms.mdx/ # машиночитаемые документы для ИИ
│   └── og/                  # созданных изображений Open Graph на странице
├── content/docs/            # ← Сгенерировано из ../docs (git-игнорируется, не редактировать)
├── docs.sync.config.mjs     # какие документы публикуются + их фрагмент/раздел/значок
├── scripts/sync-docs.mjs    # зеркала ../docs/*.md -> content/docs/
├── lib/
│   ├──shared.ts # имя сайта, URL-адреса, ссылки GitHub/Discord
│   ├── source.ts # Источник контента Fumadocs + значки боковой панели
│   └── layout.shared.tsx # общие параметры навигации/заголовка
├── components/              # MDX-компоненты, диалог поиска, корневой поставщик
├── cloudflare/router/        # Рабочий, который монтирует этот сайт в openspec.dev/docs.
├── next.config.mjs          # конфигурация статического экспорта
└── source.config.ts         # Конфигурация коллекции Fumadocs MDX
```

создан с помощью [Fumadocs](https://fumadocs.dev).
